# 日语 SEO 流量倍增 — 4 周冲刺计划（v0.1）

> **目标**：ja 自然搜索流量 +100%（8~12 周窗口内兑现，第 4 周产出全部弹药）。
> **核心判断**：精选 31 个选题是打样体量。流量翻倍靠三杠杆组合——**承接面扩大（程序化矩阵）× CTR 修复 × 排名提升**，不是单靠文章数量。

---

## 一、流量模型与目标拆解

```
ja 流量 = Σ ( 页面收录数 × 平均曝光/页 × CTR × 排名系数 )
```

| 杠杆 | 动作 | 贡献占比（估） |
|------|------|--------------|
| ① 承接面扩大 | 新增收录页（程序化矩阵 + 精选 Track） | ~70%（基线已证实：ja 非品牌为零，只能靠建池） |
| ② CTR 修复 | 高曝光低点击页 TDK/意图重写（ja 侧暂无存量，主要作用于品牌查询落地页） | ~15% |
| ③ 排名提升 | hub-spoke 内链 + pillar 权重 + 外链 | ~15% |

**基线数据（2026-10-09 已确认，GSC 28 天实测）**：
- **jpn：8,693 点击 / 82,753 曝光，CTR 10.5%，平均排名 6.7**（≈310 点击/天）→ +100% 目标 = 非品牌内容页新增 ≥8,700 点击/28d
- **决定性发现：jpn 100% 是品牌词流量**（lovart / lovart ai / loveart），日语非品牌查询 = 0，`/ja/` 页面无一进入 Top 页面 → 日语非品牌 SEO 是**从零建池**，增速天花板高但无存量可吃
- 品牌需求侧健康（CTR 10.5% 远超全站均值），说明日本有真实品牌认知，缺的只是非品牌承接面——与竞品分析「Lovart 非品牌词差竞品中位 267 倍」结论互证
- 数据管线事故修复：服务器 Trident 引擎 5 脚本曾被开源化版本覆盖（SITE 占位符）+ `brand_match.py`/`gsc-token.json` 路径缺失 → 10-04 起每日 GSC 拉数全失败。2026-10-09 已修复（备份 `scripts.bak-20261009`），次日 08:00 timer 应恢复，需验证

**关键前提（W1 剩余）**：
2. **技术体检**：`/ja/` 前缀 sitemap 收录率、IndexNow 是否覆盖 ja 新页、hreflang 一致性（`sitemap-update` Skill + sentinel 日报）。
3. **EN 库存确认**：Sanity studio Tools/Features EN SSOT 与 ja 现有 5 篇 slug（防冲突）。

> ⚠️ 基线未出前的所有篇数都是结构性预估；W1 末按真实基线校准「每页目标曝光」，矩阵可增删。

## 二、产能方案：四轨并行

### 轨道 1｜精选内容线（沿用选题清单 v0.2，31 篇不变）

按 v0.2 批次执行（第 1 批 B1/B2/S1/E1 + T 组存量）。这条线负责**质量锚点和 pillar 权重**，不扩量。

### 轨道 2｜程序化矩阵线（新增，本计划的主力增量）

借鉴竞品已验证打法（`competitor-analysis-core-keywords.md`）：
- **Higgsfield**：/tools/ 4400 页矩阵 → 我们做 ja 任务词 × 平台/场景组合矩阵
- **CapCut**："How to Use" 教程 + hub-spoke 互链 → 「〜 作り方」长尾簇
- **Venngage**：topic/ 品类入口 → S1/E1 双 pillar 收口

**矩阵组合规则：任务词（市场确认词簇）× 平台/平台規格 = 独立页**

| 矩阵 | 组合公式 | 页数 | 说明 |
|------|----------|------|------|
| EC 矩阵 | {商品画像, 商品ページ, 出品画像, 広告素材} × {楽天市場, Amazon, Yahoo!ショッピング, メルカリ, Shopify, TikTok Shop} | 24 | 每平台規格是**真实唯一数据**（楽天/Amazon 出品画像規格不同），天然规避 thin content |
| SNS 矩阵 | {投稿画像, サムネイル, バナー, 動画字幕} × {X, Instagram, TikTok, LINE公式アカウント} | 16 | 平台词由市场团队确认；尺寸規格为唯一数据 |
| 規格表矩阵 | 各平台 画像サイズ・容量 一覧（タイプ別） | 8 | 高意图、模板化、易排名；程序化 SEO 经典款 |
| 作り方矩阵 | 「{任务} 作り方 {工具/平台}」How-To 簇 | 20 | CapCut 打法；挂对应 Tools 页互链 |
| 用途矩阵 | AI 画像生成 × {ロゴ, アイコン, 名刺, チラシ, コピペ可テンプレ…} | 12 | 承接 B2 pillar 的长尾散射 |
| **小计** | | **~80** | |

### 轨道 3｜CTR 修复线（新增，杠杆 ②）

GSC ja 数据到位后筛「高曝光低点击」页（参照缺口分析 §3.5 机会词打法：曝光 >1K 且 CTR <1% 且排名 5~20 位），**重写 TDK + 开头意图匹配**，不整篇重写。预估 10~15 页，单页 30 分钟级。

### 轨道 4｜技术与权重线（杠杆 ③）

- ja 页面全量进 sitemap + IndexNow 推送（发布管道自动触发）
- S1/E1 双 pillar 收口全部 Track B + 矩阵页内链（hub-spoke 图见 v0.2 第二节）
- B4/B6 对比页 + F1 版权页定向申请 ja 行业站外引用（外链杠杆，人工）

## 四、程序化批量质量风控（红线）

批量生产最大的风险不是慢，是**质量塌方反噬全站质量信号**。红线如下：

1. **每页唯一数据源**：規格/尺寸/费用类内容必须用真实規格数据（楽天 vs Amazon 規格、各 SNS 尺寸），禁止同一模板只换平台名。
2. **日语写作规则不可豁免**：矩阵页同样执行 RULES-80 ja 细则 + L5 i18n 门禁 + `i18n-ja-bad-001.md` 负面样本规避。
3. **门禁通过率熔断**：某批次 BLOCK 率 >30% → 停批，修模板再跑（Loop 既有熔断机制）。
4. **收录监控**：新页 7 日收录率 <60% → 排查 sitemap/IndexNow，而非继续加页。
5. **表达映射纪律**：矩阵页文案遵守词簇 3 规则（個人事業主，禁「超級個体」）；平台例子按页面对应平台走，禁止全站统一例子。
