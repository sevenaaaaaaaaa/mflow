# 技术实战：5 工具串联搭建 AI 创意内容全自动生产线

> **难度**：中级 | **涉及技术栈**：Docker、n8n 工作流编排、Postiz API、Webhook、Node-based Video Pipeline  
> **适用场景**：品牌视觉自动化 + 短视频批量生产 + 多平台分发  
> **阅读时长**：15 分钟 | **可复现性**：完整可操作

---

## 概述

本文将详细拆解一条基于开源/免费工具的 AI 创意内容自动化生产线。核心思路是利用 5 个工具的 API 与文件系统进行数据流转，实现从灵感采集到多平台发布的全流程自动化。

**工具链：** [Liblib](https://www.liblib.art/inspiration) → [Lovart](https://www.lovart.ai) → [LibTV](https://www.libtv.ai/) → [n8n](https://github.com/n8n-io/n8n) → [Postiz](https://github.com/gitroomhq/postiz-app)

---

## 一、架构总览

### 1.1 数据流拓扑

```
[Liblib 灵感引擎]
    │ 输出: prompt关键词 + 风格参考
    ▼
[Lovart Brand Kit]
    │ 输出: 品牌视觉素材 (.png/.jpg, 多尺寸)
    ▼
[LibTV 节点工作流]
    │ 输出: 成品视频 (.mp4, 1080p/4K)
    ▼
[n8n 编排引擎]  ◀── Webhook / 定时触发 / 文件监听
    │ 动作: 检测新文件 → 读取元数据 → 调用 Postiz API
    ▼
[Postiz 分发层]
    │ 输出: 6+ 平台同步发布
    ▼
[监控 & 通知] (飞书/钉钉/Slack Webhook)
```

### 1.2 工具选型理由

| 工具 | 核心能力 | 技术特性 | 部署方式 | 月成本 |
|------|---------|---------|---------|--------|
| [Liblib](https://www.liblib.art/inspiration) | 灵感搜索 + 工作流复制 | Web 端，无需部署 | SaaS | 免费 |
| [Lovart](https://www.lovart.ai) | Brand Kit + AI 出图 | Web 端，支持 API（计划中） | SaaS | ¥99/月 |
| [LibTV](https://www.libtv.ai/) | 节点式视频管线 | Web 端，支持 Webhook 回调 | SaaS | 免费/按量 |
| [n8n](https://github.com/n8n-io/n8n) | 可视化工作流编排 | Node.js, 400+ 集成节点 | Docker 自托管 | 免费 |
| [Postiz](https://github.com/gitroomhq/postiz-app) | 多平台社媒管理 | TypeScript, REST API | Docker 自托管 | 免费 |

## 二、环境部署

### 2.1 n8n 部署（Docker）

```bash
# 拉取 n8n 镜像并启动
docker run -d \
  --name n8n \
  --restart unless-stopped \
  -p 5678:5678 \
  -v n8n_data:/home/node/.n8n \
  -e N8N_SECURE_COOKIE=false \
  docker.n8n.io/n8nio/n8n
```

启动后访问 `http://localhost:5678`，创建管理员账号即可。

**推荐配置：**
- 挂载本地目录用于文件监听：`-v /path/to/libtv/output:/data/libtv_output`
- 启用 Webhook：确保 n8n 实例有固定公网地址（ngrok/frp 或云服务器）

### 2.2 Postiz 部署（Docker）

```bash
# 克隆仓库
git clone https://github.com/gitroomhq/postiz-app
cd postiz-app

# 启动服务
docker compose up -d
```

Postiz 默认运行在 `http://localhost:3000`。部署后完成以下配置：
1. 创建管理员账号
2. 在 Settings → API Keys 中生成 API Token（供 n8n 调用）
3. 在 Channels 中逐个授权目标平台（微信公众号、小红书、抖音、B站、Twitter/X 等）

## 三、各环节技术实现

### 3.1 灵感采集：Liblib 工作流复制机制

**技术要点：**

Liblib 的"工作流复制"本质上是对 Stable Diffusion 生成链路的参数化存储。每个作品包含：
- 基础模型（Checkpoint）
- LoRA 叠加（权重、触发词）
- VAE / ControlNet 配置
- Prompt（正向 + 反向）
- 采样参数（Steps, CFG Scale, Sampler）

**操作流程：**
1. 访问 [Liblib 灵感广场](https://www.liblib.art/inspiration)，使用三元组搜索（场景+风格+情绪）
2. 进入作品详情页 → 查看"生成信息"面板 → 点击"复制工作流"
3. 在工作区中微调参数（替换 prompt 关键词、调整 LoRA 权重）
4. 生成的 prompt 模板导出为文本，作为 Lovart 输入

**建立灵感库的标签体系：**
```
灵感库/
├── 产品图/
│   ├── 科技风-暗色背景
│   ├── 简约-白色背景
│   └── 场景化-办公室
├── 社交媒体/
│   ├── 小红书封面
│   ├── 公众号头图
│   └── Twitter横幅
└── 情绪文案/
    ├── 激励型
    ├── 治愈型
    └── 专业型
```

### 3.2 品牌设计：Lovart Brand Kit 体系

**技术要点：**

Brand Kit 是一套设计约束的声明式配置，包含：
- **色彩系统**：主色 (Primary)、辅色 (Secondary)、强调色 (Accent)、中性色 (Neutral)
- **字体系统**：标题字体（粗体/显示）、正文字体（可读性优先）
- **Logo 规范**：深色背景版 + 浅色背景版，带安全间距定义
- **风格 Prompt**：全局风格描述词，如 "flat design, tech blue, clean layout, generous white space"

**操作路径：**

```
Lovart → Settings → Brand Kit → Create New
  ├── Upload Logo (dark + light)
  ├── Color Palette Picker
  ├── Font Selection (2-3 fonts)
  └── Style Keywords
```

配置完成后，所有出图请求自动套用 Brand Kit 约束。当前 Lovart 主要通过 Web 界面操作，API 接入请关注官方更新。

**与 Liblib 的衔接方案：**
1. 从 Liblib 导出的 prompt 作为基础描述
2. 在 Lovart 中创建项目时，将 prompt 粘贴到描述框
3. Brand Kit 自动叠加品牌风格约束
4. 生成 4-6 张变体 → 选择最优 → 导出（保持统一画布尺寸和命名规范）

**导出命名规范建议：**
```
{project}_{type}_{dimensions}_{version}.png
例：summer-campaign_product_1080x1080_v3.png
```

### 3.3 视频制作：LibTV 节点工作流

**技术要点：**

LibTV 的节点式工作流是一个有向无环图（DAG），每个节点是独立的处理单元。核心节点类型：

| 节点类型 | 功能 | 关键参数 |
|---------|------|---------|
| Image Input | 导入图片序列 | 排序规则、时长 |
| Camera Move | Ken Burns 运镜 | 缩放比例(1.0-1.3)、平移方向、缓动函数 |
| Transition | 转场效果 | 类型(溶解/滑动/淡入淡出)、持续时间(ms) |
| Text/Subtitle | 字幕叠加 | 字体、位置、动画、语音转文字 |
| Audio | 背景音乐/配音 | 音量、淡入淡出、循环 |
| Output | 渲染导出 | 分辨率、码率、格式 |

**标准工作流模板（JSON 逻辑表示）：**

```json
{
  "workflow": {
    "nodes": [
      { "id": "input", "type": "ImageInput", "config": { "duration": 4000 } },
      { "id": "camera", "type": "KenBurns", "config": { "scale": 1.15, "direction": "center", "easing": "ease-in-out" } },
      { "id": "transition", "type": "CrossDissolve", "config": { "duration": 600 } },
      { "id": "subtitle", "type": "AutoCaption", "config": { "font": "brand-font", "position": "bottom-center" } },
      { "id": "audio", "type": "BGM", "config": { "volume": 0.3, "fadeOut": 2000 } },
      { "id": "output", "type": "Export", "config": { "resolution": "1080p", "format": "mp4" } }
    ],
    "edges": [
      ["input", "camera"],
      ["camera", "transition"],
      ["transition", "subtitle"],
      ["subtitle", "audio"],
      ["audio", "output"]
    ]
  }
}
```

**批量生产策略：**
- 素材集 Prepared → 节点工作流固定 → 批量渲染 3-5 个版本
- 差异化参数：运镜方向（左/右/中）、转场时长、BGM 选择
- 输出命名：`{project}_v{1..5}_{resolution}.mp4`

**导出参数建议：**

| 平台 | 分辨率 | 宽高比 | 码率建议 |
|------|--------|--------|---------|
| 抖音/B站/小红书视频 | 1080×1920 | 9:16 | 6-8 Mbps |
| YouTube/B站横版 | 1920×1080 | 16:9 | 10-15 Mbps |
| 微信视频号 | 1080×1080 | 1:1 | 4-6 Mbps |

### 3.4 流程编排：n8n 工作流设计

这是整个生产线的核心调度层。

#### 3.4.1 触发机制

三种触发方式按需选择：

```javascript
// 方式1: Webhook 触发（推荐）
// LibTV 导出完成后 POST 到 n8n Webhook URL
{
  "video_path": "/output/summer-campaign_v1_1080p.mp4",
  "metadata": {
    "project": "summer-campaign",
    "duration": 30,
    "platforms": ["douyin", "xiaohongshu", "twitter"]
  }
}

// 方式2: Cron 定时触发
// 每小时检查一次 LibTV 输出目录
*/60 * * * *

// 方式3: 手动触发
// 测试/调试阶段使用
```

#### 3.4.2 核心工作流节点设计

```
[Webhook / Cron Trigger]
    │
    ▼
[Read Binary Files]  ← 扫描 /data/libtv_output/*.mp4
    │
    ▼
[IF Node] → 有新文件？
    │ 否 → [NoOp / Wait]
    │ 是
    ▼
[Function Node] → 解析元数据、生成各平台内容
    │
    ├─→ [Set Node: 小红书模板] → title, desc, tags, cover_size
    ├─→ [Set Node: 抖音模板] → title, desc, tags, music
    ├─→ [Set Node: Twitter模板] → text (280 chars), media
    └─→ [Set Node: 公众号模板] → title, cover, summary
    │
    ▼
[HTTP Request Node] → POST to Postiz API
    │  endpoint: POST /api/posts
    │  headers: Authorization: Bearer {POSTIZ_API_KEY}
    │  body: { channelId, content, media, scheduledAt }
    │
    ▼
[IF Node] → 发布成功？
    │ 否 → [Error Trigger] → [Webhook: 飞书/钉钉告警]
    │       └── [Wait Node: 60s] → [Retry: 最多3次]
    │ 是
    ▼
[Webhook Node] → 发送成功通知
    │  飞书/钉钉/Slack 消息: "✅ {project} 已排期，预计 {time} 发布"
    │
    ▼
[Function Node] → 记录日志到数据库/Notion
```

#### 3.4.3 模板变量的 Function Node 示例

```javascript
// n8n Function Node: 根据平台生成差异化内容
const platforms = [
  {
    id: 'xiaohongshu',
    name: '小红书',
    template: {
      title: '${project_name} | ${hook_keyword}',
      description: '${long_form_description}\n\n#${tag1} #${tag2} #${tag3}',
      coverSize: '1080x1440',
      optimalTime: '20:00'
    }
  },
  {
    id: 'douyin',
    name: '抖音',
    template: {
      title: '${hook_keyword} #${challenge_tag}',
      description: '${short_description}',
      music: '${bgm_track_id}',
      optimalTime: '12:00'
    }
  },
  {
    id: 'twitter',
    name: 'Twitter/X',
    template: {
      text: '${hook_text_280chars}',
      optimalTime: '09:00'
    }
  }
];

// 为每个平台生成发布任务
return platforms.map(p => ({
  channelId: p.id,
  content: interpolate(p.template, item.metadata),
  mediaUrls: [item.videoUrl],
  scheduledAt: calculateOptimalTime(p.template.optimalTime)
}));
```

#### 3.4.4 Postiz API 调用示例

```bash
# 创建发布任务
curl -X POST https://your-postiz-instance/api/posts \
  -H "Authorization: Bearer ${POSTIZ_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "channelId": "xiaohongshu",
    "title": "夏季新品 | 清凉一夏",
    "content": "长文描述内容...\n\n#夏季新品 #科技生活 #好物推荐",
    "media": ["https://cdn.example.com/video.mp4"],
    "coverImage": "https://cdn.example.com/cover.jpg",
    "scheduledAt": "2025-06-20T20:00:00+08:00"
  }'

# 查询发布状态
curl https://your-postiz-instance/api/posts/{postId}/status \
  -H "Authorization: Bearer ${POSTIZ_API_KEY}"
```

## 五、监控与容错

### 5.1 n8n Error Trigger 配置

在 n8n 工作流中添加 Error Trigger 节点：

```yaml
Error Handling:
  - Max Retries: 3
  - Retry Interval: 60s (exponential backoff)
  - On Final Failure:
      - Webhook: POST to 飞书/钉钉/Slack
      - Message: "🚨 Pipeline Failed: {workflow_name} at {node_name}"
      - Context: {error_message}, {input_data}, {timestamp}
```

### 5.2 常见故障排查

| 故障现象 | 根因分析 | 解决方案 |
|---------|---------|---------|
| n8n Webhook 无响应 | 网络不通 / URL 变更 | 检查 ngrok/frp 隧道状态，验证 Webhook URL |
| Postiz API 返回 401 | API Key 过期或无效 | 在 Postiz Settings 中重新生成 API Key，更新 n8n HTTP Request 节点的 Authorization Header |
| LibTV 输出文件未触发 | Webhook 未配置 / 文件路径错误 | 检查 LibTV 导出回调设置，确认文件输出到 n8n 挂载目录 |
| 平台发布失败 (个别) | 平台 API 限流 / Token 过期 | 检查 Postiz Channel 状态，重新授权该平台，加入 Rate Limiting 延迟 |
| 视频被压缩 | 分辨率/码率不匹配平台要求 | 在 LibTV 导出节点中按平台参数表设置 |

### 5.3 日志与回溯

n8n 每次 Execution 保留完整的 Input/Output 数据，可在 Execution History 中回溯每条内容的完整链路：什么时间、用什么 prompt、生成什么素材、发布到了哪些平台、成功/失败状态。

## 七、进阶架构

```

    │
    ▼
n8n HTTP Request → 抓取 Postiz / 各平台 Analytics API
    │
    ▼

    │
```

## 八、适用场景评估

### ✅ 适合的技术场景
- 独立创作者 / 自媒体技术栈
- 小型团队 (1-3人) 的内容运营自动化
- 品牌方批量视觉内容生产
- 跨境电商多平台多语言内容分发
- 知识付费/课程制作者的标准化视觉产出

### ⚠️ 需要评估的场景
- 追求极致艺术品质：AI 视觉存在上限
- 实时热点响应：自动化更适合计划性内容
- 超长视频 (>5 min)：LibTV 更擅长短视频
- 纯文字内容：本工作流视觉优先

### ❌ 不适合的场景
- 高度定制企业宣传片（需专业拍摄）
- 纯文字深度内容（小说/深度报道）
- 版权严格场景（AI 内容版权仍有灰色地带）
