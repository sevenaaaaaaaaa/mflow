# MFlow 使用指南

> 核心定位 · Features · 具体用例。写给"要规模化内容产能的内容负责人 / 独立创作者",
> 也是官网改版的素材源(与本 README 同源维护)。

---

## 核心定位

**MFlow 是一条内容生产管线:情报监测 → 内容生产 → 质量门禁 → 发布分发 → 数据回流。它是 OpenFlow 用户的进阶内容管线,亦可完全独立使用。**

你让 AI 帮你写内容,最怕三件事:写着写着跑偏、质量越来越水、这次积累的经验下次归零。市面工具帮你"生成一篇",MFlow 管的是整条产线——进度由 12 阶段状态机记录,质量由可执行钩子把关,经验沉淀进知识树和项目记忆。人只看结果,只做一件事:授权发布。

它不是演示脚本,是正在生产环境干活的系统:CMS 生产库 8,247 篇文档、Blog/News 10 种语言全量、单批次 43 篇 P0 刊文、404 修复战役累计 169+ 页(全部 HTTP 200 验证)。选题来自真实数据(GSC/GA4/Bing + Sentinel 22 源舆情),成稿要过四道质量门禁,发完有周报月报告诉你哪篇带来了流量和 AI 引用。

## Features(按你将真实用到的顺序)

### 1. 第一天:先看管线快照
`pipeline_state.py summary` 一条命令给你整条管线的当前快照:每篇内容在哪个阶段、下一步该谁。没有 CMS / LLM Key 也能先跑通 Demo 闭环(控制台「一键导入 Demo 数据」)。

### 2. 每日情报:GSC + Sentinel 22 源
`run-daily-pipeline.sh` 定时跑:GSC 拉数 → Sentinel 22 源采集 → 舆情日报 → 规则同步,launchd(macOS)/ systemd(服务器)无人值守。选题不靠拍脑袋,来自搜索表现和全网舆情。

### 3. 派工:任务路由器
23 条决策矩阵回答"这个任务该谁干、加载什么技能",实测比单档案全量加载省 86.7% token、零步骤漏失。多个 AI 工具入口共享同一份事实,互不打架。

### 4. 生产:Agent 模式或节点流水线
控制台「创作中心」两条路:Agent 模式填主题自动「生成 → 质检 → 按反馈重写」≤3 轮;节点流水线逐步点执行。Blog / Landing / Tools / Features / Topic 五类体裁,10 语言重写而非翻译。

### 5. 质量门禁:BLOCK 就是 BLOCK
写前 / 写后 / 导入前 bash 检查 + Anti-Slop 规则 + L1/L2/L3 三层质量关。非法状态转换直接拒绝(exit 2),模型"善意绕过"行不通。门禁输出写明触发项,修正后重跑。

### 6. 发布:无头 CMS / WordPress / Webhook 多出口
增量导入、Sitemap / IndexNow 自动提交、四轨道分发。发布类动作永远人工授权——管线把稿子备好,点不点"发布"在你。

### 7. 回流:周报月报 + GEO 引用缺口
SEO 周报 / 月报强制环比;探测 AI 引用缺口自动生成改稿任务。效果说得清,不再"发了就忘"。

### 8. 让 AI 工具直接驱动:MCP 17 工具
Claude / Cursor / 自研 Agent 经 MCP 检索内容库与知识库、查任务、跑预设(强制 dry-run)、看执行画布;Web 控制台与 MCP 同机运行(默认 `127.0.0.1:8088`)。

## 具体用例(可直接照抄的实战路径)

### 用例 A · 批量产文过门禁(内容团队)
1. 跑 `session-init.sh` 过 4 道会话门禁,再看 `summary` 确认管线状态;
2. 每日管线拉回 GSC 数据与舆情日报,信号驱动生成选题队列;
3. 控制台「创作中心」选 Agent 模式,按主题批量发起 → 每篇自动走「生成 → 质检 → 重写」;
4. 停在 S4-qa 的稿子人工审阅,被门禁 BLOCK 的按提示逐项改;
5. 审过的稿授权发布 → CMS 增量导入 + IndexNow 推送收录。
**结果**:单批 43 篇 P0 刊文的吞吐已被验证;产能从"一周憋几篇"变成"一批一批过门禁"。

### 用例 B · 404 修复战役(SEO / 站点维护)
1. 用 `mflow_check_url` 批量检查失效链接;
2. 问路由器 `decide --stage ... --scenario ...`,确认修复任务该走哪条预设;
3. 跑修复预设——强制 dry-run 先预览将做什么,不碰生产库;
4. 真人会话里确认后真实执行,每页以 HTTP 200 验证收尾。
**结果**:累计 169+ 页修复全部验证通过;死链不再靠人一条条翻。

### 用例 C · 多语言内容(跨境团队)
1. 同一选题选定目标语言(支持 10 语言);
2. 管线按"重写而非翻译"产出各语言版本,各按母语表达,不是机翻腔;
3. 各语言版本分别过质量门禁,再分别导入 CMS。
**结果**:Blog / News 10 种语言全量管理已实证;一套选题,多语言产能。

### 用例 D · GEO 引用感知周报(在意 AI 流量的人)
1. 每周管线跑完,到「报告中心」看 SEO 周报(强制环比);
2. 看 GEO 引用缺口清单:哪些内容被 AI 引用了、哪些该被引用却没有;
3. 缺口自动生成改稿任务,排进下一批生产。
**结果**:AI 时代的引用份额从"看不见"变成"每周有清单、有改稿动作"。

## 常见问题

**Q:没有大模型 / CMS API Key 能用吗?**
能。控制台「一键导入 Demo 数据」后,生成 → 质检 → 状态机推进的完整闭环不需要任何 Key;接真实数据源时再配凭证(放 `secrets/`,永不入 git)。

**Q:质量门禁 BLOCK 了怎么办?**
门禁输出会写明触发项。修正后重跑;确需放行走人工审阅,没有"悄悄绕过"这条路。

**Q:会自动发布吗?**
不会。发布类动作永远人工授权;MCP 不开放写生产库的动作(发布 / 真实修复),预设执行一律强制 dry-run。

**Q:WordPress 分发是什么状态?**
骨架实现:发布端各家适配需逐家联调,"兼容度优先"是设计目标,不是已盖棺的测试结论。无头 CMS 出口已在生产验证。

**Q:必须配合 OpenFlow 吗?**
不必。只要内容产能,MFlow 单独跑就成立;已在用 OpenFlow 则账号直接登录、机器 API(`X-MFlow-Token`,仅 GET)只读拉数,前台与产线同机协作。

**Q:部署要求高吗?**
Python 3.12+,clone 到任意目录即可运行——所有脚本按自身位置推导路径,无需改硬编码;控制台与 MCP 同机,默认 `127.0.0.1:8088`。

- **配 OpenFlow**:账号互通已上线,OpenFlow 管前台与业务,MFlow 管内容产线;业务信号(订单 / 咨询热词)可喂给选题队列。
