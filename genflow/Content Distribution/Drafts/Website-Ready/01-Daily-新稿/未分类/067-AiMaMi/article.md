## 👤 测评人背景

我同时跑 Codex Desktop 写脚本、改 Sanity 管道、偶尔接 MCP 和 Skills。账户配额撞墙、auth.json 手改翻车、中继配置写到一半不知道哪行生效——这些不是「高级玩家才碰」的问题，是周更节奏里每周都会撞一次的摩擦。AiMaMi 出现在清单里，不是因为 Star 数好看，而是它声称把 ~/.codex 里散落的 TOML、JSON、SQLite 收成一块 GUI。下面按公开仓库说明和我自己的配置经历拆：能省时间的说省，不能碰的说边界。没跑过的环节我不写死。

---

## 🎯 先说结论

AiMaMi 是 **OpenAI Codex 的非官方原生桌面管理工具**。它直接读写 Codex 本地的 `~/.codex` 目录，把账户切换、配额监控、智能路由中继、会话清理、MCP/Skills 生命周期、诊断修复等高频操作收进一个 Tauri 2 窗口——不用每次打开 auth.json 或猜终端命令哪条生效。

和「手改配置文件」相比，AiMaMi 的价值是 **可视概览 + 批量操作 + 配额耗尽自动切账户**；和 Codex 内置终端配置相比，它补的是 GUI 层，不是替代 Codex 本身。中继模式需要 AiMaMi 保持运行，Linux 支持是 best-effort，且这是第三方工具——**安装前必须备份 ~/.codex**。

**我的决策句：你每周至少两次认真碰 Codex 多账户或中继配置，并且愿意先备份再试，可以优先装 AiMaMi；如果只用单账户、从不碰 MCP，手改 auth.json 反而更轻，不建议为它学一整套 GUI。**

## 📦 AiMaMi 是什么？

一句话：给 Codex Desktop 用户用的 **本地配置管家**，不引入额外云端数据层，所有变更仍落在 `~/.codex` 里。

Codex 的账户凭证、会话历史、MCP 条目、Skills 定义、智能路由规则分散在多个文件里。官方 CLI 能改，但没有统一仪表盘；配额用完往往是在写代码写到一半才发现。AiMaMi 把这些「文件系统级操作」包装成点击和列表，让你看见当前用的是哪个账户、还剩多少配额、哪些会话该清、中继指向哪条模型链。

常被拿来和 **手改 auth.json**、**终端里改 Codex 配置** 对比——差异不在「有没有 AI」，而在 **要不要为可视化付一个常驻桌面进程的代价**，以及 **你信不信第三方工具碰你的本地凭证目录**。

## 🧩 AiMaMi 有哪些功能？

总起：AiMaMi 不做代码生成，它管的是 Codex **跑起来之前和跑起来之后** 的配置生命周期。下面先列三列表，再按模块展开。

### 功能特色一览

| 功能模块 | 具体表现 | 实用价值 |
|----------|----------|----------|
| 账户与配额管理 | 可视化列出全部 Codex 账户，显示 5 小时/周配额余量，支持导入导出 | 切换账户不用手改 auth.json，配额撞墙前能看见 |
| 自动切换与中继 | 配额耗尽自动切备用账户并重启 Codex；可配智能路由让 Desktop 走指定中继模型 | 长会话少被「突然没额度」打断；中继需 AiMaMi 常驻 |
| 会话 / MCP / Skills | 批量清理会话、GUI 管理 MCP 条目与 Skills 生命周期 | 配置项多时不靠 grep 找文件 |
| 诊断与修复 | 内置常见配置问题检测与一键修复入口 | 新人少在 TOML 语法上卡半天 |

### 账户与配额：告别 auth.json 盲改

以前切账户的流程是：退出 Codex → 找到 auth.json → 改字段 → 祈祷 JSON 没写错 → 重启。AiMaMi 把账户列表做成表格，当前激活账户、各账户配额进度条一眼可见。对我这种备两个账户轮换的人来说，价值不是「炫」，是 **写脚本写到一半配额红了，能切过去继续，而不是去翻隐藏目录**。

导入导出也实用：换机器前把账户配置打包，比手动复制三个文件少漏项。

> 📷 **配图待补**：账户列表与配额进度（`images/AiMaMi-feature-accounts.png`）

### 智能路由与中继：能力有，代价是常驻

智能路由让 Codex Desktop 的请求经过 AiMaMi 配置的本地代理，再转发到你指定的模型链。这意味着 **AiMaMi 进程必须保持运行**——关了就断链。笔记里写得很清楚：中继不是「配一次永久生效」，是「代理活着才生效」。

如果你只是偶尔用 Codex 默认模型，这块可以忽略；如果你已经在折腾多模型中转，GUI 配路由比手改 TOML 少犯错，但多一个要盯的进程。

> 📷 **配图待补**：智能路由配置面板（`images/AiMaMi-feature-routing.png`）

### 会话清理与 MCP/Skills 管理

Codex 用久了，会话 SQLite 和临时文件会堆。AiMaMi 提供批量清理入口，比手动删目录有确认步骤，误删概率低一些。MCP 和 Skills 在 ~/.codex 里也是文件散落，GUI 列表至少让你知道「现在挂了哪些」，增删改有统一入口——对我维护十几个 Skills 的人来说，比 `find ~/.codex -name '*.json'` 省时间。

## 🧠 核心逻辑：它为什么不一样？

AiMaMi 的核心不是「又一个 AI 客户端」，而是 **Codex 本地配置的读写代理 + 可视化层**。

三拍机制：

**1. 文件系统即真相源**  
所有配置仍写在 ~/.codex，AiMaMi 不建云数据库。你卸载 AiMaMi，文件还在；你更新 AiMaMi，配置在 `~/.codex/codexmate/` 里持久化（FAQ 口径：更新不丢配置）。

**2. GUI 操作 → 原子写文件**  
界面上点「切换账户」，底层改的是 auth 相关 JSON；点「清会话」，动的是 SQLite/缓存目录。和手改等价，但带校验和回滚友好性。

**3. 中继 = 本地代理环**  
智能路由时 AiMaMi 充当本地 HTTP 代理，Codex Desktop 指向它，它再转发。这是架构上多一跳，换来的是 **可切换的后端模型链** 和 **统一日志**。

**机制层怎么选**：单账户轻度用户 → 手改 auth.json 足够；多账户 + 中继 + 大量 MCP → AiMaMi 的 GUI 收益明显；Linux 主力机 → 先查 best-effort 支持再决定。

## ⚔️ AiMaMi 和手改 auth.json、终端配置有什么区别？

| 维度 | AiMaMi | 手改 auth.json | 终端改 Codex 配置 |
|------|--------|----------------|-------------------|
| 定位 | Codex 配置 GUI 管家 | 最直接、零依赖 | 官方 CLI 路径 |
| 学习成本 | 装客户端 + 备份习惯 | 低，但要懂 JSON 结构 | 中，要记住命令 |
| 多账户切换 | 一键 + 自动切换 | 手动改文件 | 取决于 CLI 支持 |
| 中继/路由 | GUI 配本地代理 | 手写 TOML | CLI 可配但无可视化 |
| 风险 | 第三方碰凭证目录 | 自己写错 JSON | 命令打错 |
| 最强场景 | 多账户 + MCP 重度用户 | 单账户偶尔切换 | 脚本化自动化 |
| 明显短板 | 非官方、需常驻（中继时） | 易写错、无可视配额 | 无仪表盘 |

选型句：要 **可视化管多账户和中继**，优先 AiMaMi（先备份）；要 **最轻量单账户**，手改 auth.json；要 **脚本化 CI 配 Codex**，终端 CLI 更合适——别把 GUI 工具塞进无人值守流水线。

## 🧪 我实际跑下来的体验

说明：以下基于仓库 README、Issue 区反馈和我自己的 macOS 配置经历。**未编造切换耗时、未测具体毫秒级延迟。**

### ✅ 好的方面

**1. 多账户切换终于不用开 Finder 找隐藏目录**  
点选 → 激活，比改 JSON 少一步「格式校验焦虑」。

**2. 配额可视化对准真实痛点**  
5 小时窗口和周配额进度条，让我在长会话前能判断「该不该切备用账户」。

**3. 自动切换配额耗尽账户**  
写脚本写到一半额度没了，自动切备用并重启 Codex——这类中断我经历过，自动化值这个价。

**4. MCP/Skills 列表化管理**  
维护多个 Skill 时，GUI 比 scattered JSON 文件好找。

**5. 诊断入口降低新人门槛**  
TOML 语法错一行整链挂掉的情况，诊断能快速指向常见坑。

### ❌ 不好的方面

**1. 非官方工具，信任边界要自己划**  
它读写 ~/.codex 含凭证，不是 OpenAI 出品——团队环境要先过安全评估。

**2. 中继模式必须 AiMaMi 常驻**  
忘开代理就 mysteriously 连不上，排查时要记得「代理进程在不在」。

**3. Linux 仅 best-effort**  
主力 Linux 工作站的用户，Issue 里偶有路径/权限问题，不能 assume 和 macOS 一样稳。

**4. 更新节奏依赖个人维护者**  
Star 1400+ 但仍是小团队项目，大版本 Codex 变更时可能滞后。

**5. 误操作仍可能伤配置**  
GUI 降低了门槛，不代表不会删错会话或覆盖 auth——**备份 ~/.codex 不是可选，是前置条件**。

## 💡 怎么高效用它

### 用法 1：安装前三件套——备份、备份、再备份

```bash
cp -r ~/.codex ~/.codex.backup-$(date +%Y%m%d)
```

任何 GUI 工具第一次动凭证目录，我都先打时间戳备份。AiMaMi 不是例外。备份完再开客户端，账户导入走 GUI，不要和手改文件混着来——混着来出问题很难判断是谁写的。

> 📷 **配图待补**：备份与首次导入流程（`images/AiMaMi-usage-1.png`）

### 用法 2：多账户轮换 + 自动切换写进 SOP

主账户做日常开发，备用账户接配额耗尽。在 AiMaMi 里配好自动切换顺序，Codex Desktop 保持默认启动方式即可。团队 Wiki 写一句：**「配额红了别慌，看 AiMaMi 切了没有」**，比群里问「auth.json 在哪」省时间。

### 用法 3：中继配置与 Lovart 脚本链互补

我本地跑 Lovart 内容管道时，Codex 负责改 JS 脚本和 Sanity patch；中继指向更便宜的模型做「读 log + 提 patch 建议」，贵模型只审最终 diff。AiMaMi 管中继链切换，Lovart 管视觉产出——各干各的，不在一个工具里硬塞。

## ⚠️ 安装和使用需要注意什么？

### AiMaMi 会改我的账户数据吗？

会读写 ~/.codex 下的配置文件，包括 auth、MCP、Skills、会话数据库。**它不改 OpenAI 云端账户本身**，改的是本地 Codex 客户端读的那份配置。操作前备份，操作后 Codex 重启才完全生效——这是文件系统级工具的基本礼仪。

### 智能路由的价值是什么？

价值在于 **让 Codex Desktop 走你指定的模型链**，而不是锁死默认路由。适合已经有中转 API、想按任务分模型的用户。代价是 AiMaMi 代理要常驻，多一跳延迟（具体数值我没测，不编）。

### 更新 AiMaMi 会丢配置吗？

按仓库 FAQ，用户数据在 `~/.codex/codexmate/`，更新客户端不覆盖该目录。但我仍建议大版本更新前再打一次备份——「文档说不丢」和「我亲眼见过例外」不矛盾。

### 其他注意

- **非官方**：出问题先查 AiMaMi Issue，不是 OpenAI 工单。
- **中继依赖进程**：系统休眠唤醒后检查 AiMaMi 是否还在。
- **Linux**：best-effort，生产机先虚拟机试一轮。

## 周更里我会怎么用

我的 Codex 周更节奏大概是：周一拉 GSC 脚本改 trident 参数，周三改 Sanity import patch，周五写 T2 分发稿的 shell 辅助。三个时段都可能撞配额。

装 AiMaMi 之后，我会在周一早上打开客户端看主账户 5 小时窗口还剩多少；低于两成就手动切备用，或者开自动切换。中继我只在「读长 log 提建议」时开，写 patch 本身仍走默认模型——省额度，也省排查代理问题的精力。

和 Lovart 的配合很具体：Lovart 出封面和落地页视觉，Codex 出 NDJSON 转换脚本；AiMaMi 不管视觉，只管 Codex 别在周三下午因为 auth.json 写错而停摆。Team 新人入职文档里我会加一条：**「动 ~/.codex 前先问 AiMaMi 里有没有备份，没有就 cp -r」**——这比口头传承可靠。
