# Context

- 用户发现 Italian (`/it/blog/`) 博客页面大量 404
- 根因：835 篇 IT blog 中有 72 篇 `_id` 带 `it.` 或 `blog.it.` 前缀，前端路由不匹配此类 _id
- 分为两类：64 篇有重复（一个 `it.` 前缀 + 一个 auto-generated _id），8 篇仅 `it.` 前缀（无其他副本）

# Solution

1. 删除 64 篇旧前缀重复文档（保留 auto-generated _id 版本）
2. 删除 8 篇 solo 旧前缀文档，用原数据 + auto-generated _id 重建
3. 处理变音字符 slug（`é` → `e`，全站唯一含重音 slug）
4. CDN/ISR 逐页预热：手动请求触发 Next.js ISR 重建

# Files Changed

No harness files changed — 所有操作在 Sanity production 数据层执行。

# Decisions Made

- D1: 有 auto-generated 副本的旧前缀文档直接 delete（64 篇）
- D2: solo 旧前缀文档先 delete 再用 `create_if_not_exists` + auto _id 重建（8 篇）
- D3: 变音字符 slug `perché` → `perche`（用户确认，全站 kebab-case 无重音规范）

# Patterns Observed

- P1: Next.js ISR 无 webhook 时，slug 冷启动需要多次请求（有时 5+ 次）才能触发构建
- P2: ISR 构建的页面缓存 TTL 短，过期后重回 404，需再次触发
- P3: 同一请求工具（Python urllib vs curl）不同 User-Agent 会导致 Cloudflare 403/404 行为不一致
- P4: Sanity `_id` 前缀（`it.`, `blog.it.`）影响前端路由，auto-generated _id 总会工作
