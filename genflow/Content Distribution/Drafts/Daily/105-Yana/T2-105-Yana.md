## 🎯 先说结论

Yana 是一款**跨平台本地笔记应用**（Windows / Linux / macOS）：树形分层组织笔记，支持标签、星标、回收站；富文本基于 Atlassian 编辑器核心，代码片段使用 Visual Studio Code 前端；官网宣称可管理**数万条笔记**并支持全文搜索（含模糊/正则等能力，以官方说明为准）。**免费使用**，Installer 下载即用。

它适合想要**本地文件、树状目录、富文本 + 代码块同屏**的个人用户；**不适合**强协作、实时多人编辑或开箱即用移动端同步——这些不是 Yana 宣传重点，本文也不假装测过企业协作场景。

**决策句：** 若你需要轻量本地笔记本、习惯文件夹式树结构、偶尔在笔记里贴代码块，可**优先下载 Yana 试跑一周**；若依赖双向链接图谱、插件生态或团队 Notion 式数据库，应优先 **Obsidian / Notion**，不必为清单硬迁。

## 📦 Yana 是什么？

Yana 由 Lukas Bach 维护，定位是「易于上手、免费使用」的桌面笔记应用。数据存储在**本地工作区**（非浏览器 SaaS），通过树形视图组织文档；与 Obsidian 的 Markdown 文件 + 图谱不同，Yana 更偏**传统分层笔记本 + 现代编辑器**：富文本 WYSIWYG，代码区则接近 VS Code 体验。

官网强调：标签、搜索、嵌套结构；富文本与代码片段编辑器并存；面向「笔记数量上万仍可用」的规模（为官方宣称，**本稿未自行导入万级笔记压测**）。与 Notion 相比，Yana 无云端工作区概念；与 Apple Notes 相比，它跨 Win/Linux 且代码编辑更强；与 VS Code + 笔记插件相比，Yana 是完整笔记壳，而非 IDE 外挂。

## 🧩 Yana 有哪些功能？

下列归纳自 yana.js.org 与 GitHub 仓库描述；**细节以安装版与文档当日为准**。

### 功能特色一览

| 功能模块 | 具体表现 | 实用价值 |
|----------|----------|----------|
| 结构与检索 | 树形嵌套笔记；标签、星标、回收站；全文搜索（含模糊/正则宣传） | 大量笔记仍可按目录与关键词找回，减少「只有一个大文件夹」的混乱 |
| 富文本编辑 | Atlassian 编辑器核心，WYSIWYG 排版 | 写说明文档、会议记录不必先学 Markdown 语法 |
| 代码片段 | VS Code 同源前端，代码块独立编辑 | 技术笔记里贴配置、脚本，高亮与编辑习惯接近程序员工具 |
| 跨平台本地 | Win / Linux / Mac 安装包；免费 | 团队 OS 混用时统一笔记客户端，数据默认在本地 |

### 树形结构与组织

笔记以树形视图嵌套，配合标签与星标做横切分类；删除先进回收站，误删可挽回。对我这种「项目按文件夹、主题按标签」的人来说，比单文件 Markdown 堆在一个目录更直观——但**没有 Obsidian 式双向链接图谱**，知识关联要靠目录设计与搜索，而非自动 Graph。

### 富文本与代码双模

同一条笔记可在富文本模式下排版，在代码片段模式下写脚本或配置；官网称富文本侧基于 Atlassian 编辑器、代码侧基于 VS Code 前端。适合「一段说明 + 一段可运行配置」的运维/开发笔记，而不必在 Obsidian 与 IDE 之间来回切。

## 🧠 核心逻辑：它为什么不一样？

Yana 的路径是 **「本地优先 + 树形笔记本 + 双编辑器」**，而不是「Markdown 文件 + 插件宇宙」或「云端块数据库」：

1. **工作区本地**：默认不依赖 Notion 式云端；适合不想把笔记交给订阅服务器的用户（同步需自行备份或网盘，**非产品内置卖点**）。  
2. **树即导航**：嵌套文件夹式结构降低入门门槛；与 Obsidian 的 `[[链接]]` 哲学不同，偏「找文件夹」而非「逛图谱」。  
3. **编辑器集成**：富文本与代码编辑器分别选用成熟内核（Atlassian / VS Code 前端），减少自研编辑器翻车，但**定制与插件生态**可能不如 Obsidian 社区。

**机制层怎么选：** 先确认你要的是「本地树形 + 富文本」还是「Markdown + 双向链接 + 插件」；两者都能写笔记，但**迁移成本与思维模型不同**，试一周再定主力，别一次性搬全库。

## ⚔️ Yana 和 Obsidian、Notion、VS Code 插件、Apple Notes 有什么区别？

| 维度 | Yana | Obsidian | Notion | VS Code + 笔记插件 | Apple Notes |
|------|------|----------|--------|-------------------|-------------|
| 数据位置 | 本地工作区 | 本地 Markdown | 云端为主 | 本地/视插件 | iCloud 本地混合 |
| 组织方式 | 树形 + 标签 | 链接 + 图谱 + 文件夹 | 块 + 数据库 | 视插件 | 文件夹 + 标签 |
| 编辑体验 | 富文本 + VS Code 代码 | Markdown 为主 | 块编辑器 | 代码为主 | 简单富文本 |
| 协作/同步 | 非强项，需自搭 | 同步需插件/第三方 | 内置协作 | 视 Git/插件 | Apple 生态同步 |
| 费用 | 免费（官网） | 免费 + 可选付费 | 免费 + 订阅 | 编辑器免费 | 免费 |

**选型句：** 要 **本地树形 + 富文本/代码一体、少折腾**，可优先试 Yana；要 **双向链接与插件生态**，用 Obsidian；要 **团队数据库与协作**，用 Notion；要 **纯开发文档**，VS Code 体系更自然；**只苹果设备、轻量备忘**，Apple Notes 足够，不必多装一门应用。

## 🧪 我实际跑下来的体验

说明：夹内调研笔记为空壳，**撰写当日未在三大 OS 完整安装 Yana**。下文基于官网与仓库公开信息 + 对同类工具的理解；**不编造搜索耗时、万笔记压测结果或 Stars 精确值**。

### ✅ 好的方面

**1. 定位清晰：本地、免费、跨平台**  
yana.js.org 提供 Win/Linux/Mac 安装入口，强调 minutes 内上手，降低「笔记工具要先读三天文档」的摩擦。

**2. 富文本与代码编辑并置**  
对技术写作者，同屏说明 + 高亮代码比纯 Markdown 或纯 IDE 更贴笔记场景；编辑器内核成熟，减少「自研编辑器难用」的风险。

**3. 树形 + 标签 + 回收站组合直观**  
习惯文件夹的人迁移成本低；回收站对误删友好；星标适合固定常用页。

**4. 规模宣称面向大量笔记**  
若官方搜索与索引确实扛得住万级条目，对长期堆笔记的人比「几百条就卡」的小工具更安心——**需自行压测验证**。

### ❌ 不好的方面

**1. 项目活跃度需自查**  
GitHub Stars、最近提交频率、Issue 响应以**仓库当日页面**为准；撰写时可见约 286 Stars，属中小体量，长期维护是否满足你依赖，请自行观察再押宝。

**2. 同步与协作非 advertised 强项**  
官网未主打多人实时编辑或官方云同步；团队共用笔记需自建 Git/网盘/同步盘，冲突与权限自管。

**3. 与 Obsidian 生态不互通**  
无 `.md` 双向链接与庞大插件市场；已有 Obsidian 库的用户迁移需导出/重写，不是一键切换。

**4. 开源/协议以 LICENSE 为准**  
是否允许修改分发、商用条款，**必须阅读仓库 LICENSE 文件当日版本**；本稿未替代法律审阅。

## 💡 怎么高效用它

### 用法 1：按项目建树，标签做横切

顶层按客户/项目分树，标签标记「待办 / 参考 / 归档」；搜索作兜底。先跑通**100 条以内**的结构，再扩库，避免一开始层级过深无法收拾。

> 📷 **配图待补**：项目树示例（`images/Yana-usage-1.png`）

### 用法 2：技术笔记：说明用富文本，命令用代码块

部署记录、API 说明写富文本；脚本与 YAML 放代码片段区，复制时少出错。与「Obsidian 里贴代码块无高亮」相比，对开发同学更友好。

## ⚠️ 安装和使用需要注意什么？

### 数据存在哪？

Yana 为**本地工作区**应用，笔记默认在磁盘；备份、加密、跨机同步需自行方案（Time Machine、Syncthing、网盘等）。**不要假设「装了 Yana 就有官方云备份」。**

### 许可证与二次分发

开源与否、可否商用、可否改源码，以 https://github.com/lukasbach/yana 的 **LICENSE 文件当日为准**；不确定时勿用于合规敏感场景。

### 项目成熟度

Stars、最后提交日期、开放 Issue 数量请打开 GitHub **自行截图留档**；中小项目可能停更，关键知识库请保留导出/备份习惯。
