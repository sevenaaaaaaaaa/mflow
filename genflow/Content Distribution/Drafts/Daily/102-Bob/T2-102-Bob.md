## 👤 测评人背景

我日常读英文文档、审外文 PR、偶尔还要从截图里抠文字。系统翻译在 Safari 里能用，但离开浏览器就断档；浏览器插件沉浸翻译很强，却管不了 PDF 里的选中句和 Finder 里的图片。Bob 是 macOS 菜单栏里的翻译 + OCR 工具，划词、截图、输入框都能唤出——官网 https://bobtranslate.com，Mac App Store 分发。GitHub 仓库 ripperhe/Bob 现在主要是联系与说明页，**产品本身闭源**。夹内笔记偏薄，事实以官网/MAS 公开口径为准；各翻译服务的计费与 Key 配置以文档当日为准。

## 🎯 先说结论

Bob 是一款 **macOS 菜单栏翻译与 OCR 软件**（系统要求官网/MAS 标注 macOS 10.13+，以商店页当日为准）。核心交互：划词翻译 ⌥D、截图翻译 ⌥S、输入翻译 ⌥A、OCR ⇧⌥S，并支持静默 OCR、访达选中图片识别等。可接入系统翻译、火山、腾讯、百度、有道、谷歌、微软、DeepL、OpenAI 等多种服务（**具体列表与可用性以官方文档当日为准**），插件体系支持多开、驼峰/蛇形拆分、PopClip 与 AppleScript 扩展。

**我的决策句：** 如果你长期在 Mac 上读外文、且希望「任何 App 里划词即译、截图即 OCR」而不想切浏览器，可以 **优先** 从 Mac App Store 装 Bob 并配好默认服务；如果你要跨平台、必须开源可审计、或不愿管理多家 API Key/账单，**不建议** 把 Bob 当唯一翻译栈，应保留系统翻译、Easydict（开源）或纯浏览器方案作对照。

## 📦 Bob 是什么？

Bob 定位是 **macOS 全局翻译与 OCR 助手**：常驻菜单栏，通过全局快捷键从当前前台 App 取词、取图或取输入框文本，再调用你配置的翻译/OCR 引擎返回结果。与「只在浏览器里工作的翻译插件」不同，Bob 的设计目标是 **跨 App**——Mail、Preview、IDE、Slack 窗口里都能划。

产品 **闭源**，通过 Mac App Store 销售/分发（价格与内购以 MAS 当日显示为准）。GitHub 上的 ripperhe/Bob 仓库不再等同于「可编译的开源客户端」，更多是开发者联系渠道与历史说明——选型时不要把它和 Easydict 等开源同类混淆。

OCR 能力含离线选项（具体语言包与精度以官网为准）；另带多种语音合成朗读。插件与「多开」面向高级用户：不同服务组合、不同快捷键策略可以拆成多实例。

## 🧩 Bob 有哪些功能？

总起：Bob 把「取内容 → 调服务 → 呈现结果」收到菜单栏一处；下表归纳公开文档中的高频模块。

### 功能特色一览

| 功能模块 | 具体表现 | 实用价值 |
|----------|----------|----------|
| 全局翻译 | 划词 ⌥D、截图 ⌥S、输入 ⌥A；支持 PopClip、AppleScript | 不离开当前 App 读外文、回消息 |
| OCR 识别 | ⇧⌥S 截图 OCR；静默 OCR；访达选中图片识别；含离线 OCR | PDF/图片/扫描件里的字可搜可复制 |
| 服务与插件 | 系统/火山/腾讯/百度/有道/谷歌/微软/DeepL/OpenAI 等；插件、多开、驼峰蛇形拆分 | 按语种与预算换引擎；开发者可扩展 |

### 划词、截图与输入翻译

**划词 ⌥D**：在前台 App 选中文字后触发，Bob 读取选区并送往默认翻译服务。适合读论文、审代码注释、看 Slack 英文线程——前提是目标 App 允许 Accessibility/选区 API 正常暴露文本（部分 PDF 阅读器、图片内文字除外）。

**截图 ⌥S**：框选屏幕区域送 OCR + 翻译一条龙。适合 UI 里是图、或 PDF 不让复制的段落。

**输入 ⌥A**：在可编辑输入框翻译当前内容，写英文邮件、填表单时少切词典 App。

> 📷 **配图待补**：划词翻译浮窗（落盘名：`Bob-feature-1.png`）

### OCR 与访达联动

**⇧⌥S** 走截图 OCR 路径；**静默 OCR** 适合批量识别场景（具体行为以版本说明为准）。访达里选中图片文件可直接走识别——做素材整理、从客户发来的 PNG 简报里抠电话/地址时省事。

离线 OCR 对无网或不愿把截图上传云端的人友好，但语言覆盖与识别率 **因语言与图片质量而异，本稿不编造识别率百分比**。

> 📷 **配图待补**：截图 OCR 与访达选图（落盘名：`Bob-feature-2.png`）

### 多服务、插件与文本处理

Bob 可配置多家翻译/OCR 后端：系统翻译免费但能力有限；DeepL/OpenAI 等通常要 Key 或订阅；国内引擎（火山、腾讯、百度、有道等）各有过户与合规要求——**接入前读官方配置文档与供应商协议**。

插件体系支持扩展；「多开」允许不同配置文件并行（例如工作用 DeepL、个人用系统翻译）。驼峰/蛇形拆分对读代码 identifier 有帮助。PopClip 与 AppleScript 接入适合已有自动化习惯的用户。

语音合成提供多种朗读声音，适合「译完听一遍」校对口吻是否自然。

## 🧠 核心逻辑：它为什么不一样？

Bob 的差异在 **macOS 全局钩子 + 服务可插拔**，而不是自研大模型：

1. **菜单栏常驻 + 快捷键**：把翻译/OCR 从「打开某个网站/App」变成「当前上下文一键调用」。
2. **服务层抽象**：同一套 UI 可换 Google、DeepL、OpenAI 或国内厂商——你买的是交互与工作流，模型能力跟所选服务走。
3. **闭源 MAS 分发**：与 Easydict 等开源方案比，安装更新走 App Store，但源码不可审计。

机制层怎么选：日常英中阅读可先用系统翻译或单一付费引擎；中日韩混排、代码文档、或需 OCR 的图片页，再配截图 OCR + 离线包。多 Key 用户用多开拆「工作/个人」配额，避免一个 Key 被全文 OCR 刷爆。

## ⚔️ Bob 和系统翻译、沉浸翻译、Easydict、截图 OCR 工具有什么区别？

| 维度 | Bob | macOS 系统翻译 | 沉浸翻译（浏览器） | Easydict | 单一截图 OCR（如 iText 等） |
|------|-----|----------------|-------------------|----------|---------------------------|

| 源码 | 闭源 | 闭源 | 视实现 | 开源可审计 | 多为闭源 |

## 🧪 我实际跑下来的体验

说明：夹内笔记偏薄，事实以官网/MAS 公开口径为准；各云端服务响应速度随网络与配额变化，**本稿不编造 ms 级延迟或 QPS 数据**。

### ✅ 好的方面

**1. 快捷键体系覆盖读、写、图三条线**

⌥D / ⌥S / ⌥A 分工明确， muscle memory 形成后少开浏览器标签。比「复制 → 切词典 App → 粘贴」少两步，日累计省时间。

**2. 截图 OCR + 翻译一条龙**

UI 截图、扫描 PDF 页、客户发来的微信长图，框选即出文字再译——系统翻译单独做不到这条链。

**3. 多服务切换灵活**

同一浮窗可换 DeepL、OpenAI 或国内引擎（以你配置的为准）。日文技术文档用 A 引擎、英文合同用 B 引擎，可通过多开或配置预设实现。

**4. 访达选图 OCR 适合素材整理**

从 Downloads 里批量选中 PNG/JPG 走识别，比一张张打开 Preview 复制快。具体是否支持你用的格式，以版本说明为准。

**5. PopClip / AppleScript 可嵌入已有自动化**

已有 PopClip 动作链或 Keyboard Maestro 脚本的用户，可以把 Bob 当一环，而不是另起一套习惯。

### ❌ 不好的方面

**1. 闭源，无法审计数据去向**

选 OpenAI、Google 等云端服务时，选区/截图会上传供应商。企业合规需单独评估；不能因「菜单栏工具」默认无风险。

**2. 部分服务必须自配 Key 或付订阅费**

DeepL、OpenAI、部分国内 API 要账单。Bob 本体价格之外还有 **服务层成本**；Key 泄露风险需靠本机 Keychain 与权限管理。

**3. 仅 macOS，团队 Win/Linux 无同款**

跨平台团队无法统一 Bob 工作流；协作者得各用各的翻译栈，术语表难对齐。

**4. 部分 App 内划词取词失败**

图片 PDF、某些 Electron App、受保护选区，划词可能空结果或乱码——这不是 Bob 独有，但「全局」预期会放大挫败感。截图 OCR 是退路，却更慢。

**5. GitHub 仓库易误导「开源」预期**

ripperhe/Bob 现主要为联系/说明，新用户若冲开源审计而来会落空。选型信息应看 bobtranslate.com 与 MAS，而非旧 Star 印象。

## ⚠️ 安装和使用需要注意什么？

### 系统与权限

- 系统要求：官网/MAS 标注 macOS 10.13+（**以商店页当日为准**）。
- 划词与 OCR 需辅助功能、屏幕录制等权限；首次使用按引导逐项打开。
- 仅 macOS，无 Windows/iOS 官方客户端（以官网为准）。

### 服务、Key 与账单

- 火山、腾讯、百度、有道、谷歌、微软、DeepL、OpenAI 等：**可用性与计费以各供应商及 Bob 文档当日为准**。
- API Key 勿提交 git、勿贴 Slack 公开频道；团队 Key 应轮换与限额。
- 系统翻译无需 Key，但语种与质量有限。

### 隐私与合规

- 闭源客户端 + 云端引擎：敏感合同、未公开财报、客户 PII 默认不应走截图 OCR 上传。
- 离线 OCR 可降低外传面，但仍需读 Bob 隐私政策与本地缓存行为。
- 医疗、金融、政务场景可能需要禁止第三方翻译——**制度优先于工具方便**。

### 购买与更新

- 以 Mac App Store 页面价格、内购与更新策略为准；勿信第三方「破解版」，有 Key 泄露与恶意软件风险。
