# Context
- i18n 管线名实不符:SKILL.md 说"重写不是翻译",但脚本是 translate-md-batch.py
- 9 种语言被踢出创作管线,扔进翻译管线
- deprecated skills (lovart-blog-serp-writer / lovart-blog-automation) 幽灵引用在 9 个 skill 里

# Solution
**两层修复**:

**1. i18n 管线重构**:
- signal-writer 出口矩阵:所有 10 种语言统一走 signal-writer 创作
- i18n-pipeline 降级为"骨架派生器"(只提供 EN 骨架 + 本地化规则,不写内容)
- 老的 Python 翻译管线 (translate-md-batch.py / translate-zh-rewrite.py) 标记废弃

**2. deprecated skills 幽灵引用清理**:
- lovart-blog-serp-writer → lovart-blog-signal-writer (12 个替换,9 个 skill)
- lovart-blog-automation → lovart-blog-signal-writer (12 个替换,9 个 skill)

# Decisions Made
- D1: 所有语言版本统一走 signal-writer 创作,不走翻译管线
- D2: i18n-pipeline 降级为骨架派生器,提供 EN 骨架 + 本地化规则
- D3: deprecated skills 的引用全部指向 signal-writer,不留幽灵
- D4: 老 Python 翻译管线标记废弃,不删除(保持向后兼容)

# Patterns Observed
- P1: deprecated skills 的"幽灵引用"会通过 agent 的 skill 依赖链传播——修一个不够,要修所有引用者
- P2: i18n-pipeline 的 description 说"重写不是翻译"但脚本是翻译——名实不符是最危险的架构债
- P3: signal-writer 是 blog 创作的唯一 SSOT——所有 Blog 相关 skill 都应该指向它
