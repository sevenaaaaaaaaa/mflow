我日常做内容分发，基金估值和 Lovart 几乎无关——本稿按 Daily 单品清单写深测，不硬塞设计工具。夹内调研笔记对 Real-time Fund 基本是空壳（「待补充」占位），所以下文事实一律以 GitHub README 与官网为准；未亲自跑通的环节写「未核」，不编造刷新延迟毫秒数或 Stars 变动。

我自己持有一小撮场外基金，盘中最烦的是：天天基金 App 广告多、信息密度高；Excel 手工算估值又跟不上盘中波动；雪球社区热闹，但我只想看净值和重仓股涨跌，不想被信息流带走。基估宝（仓库名 real-time-fund）进清单，是因为 **Next.js 纯前端 + JSONP 直连公开接口 + localStorage 本地持久化** 这条路径——能自托管、能 GitHub Pages 静态部署，还能选装 Supabase 做多设备同步。

## 🎯 先说结论

基估宝是一个 **基金实时估值与重仓股追踪** 的 Web 工具：输入六位基金代码，卡片展示单位净值、估算净值、涨跌幅，并拉取前十大重仓股的盘中涨跌；数据来自天天基金、东方财富、腾讯财经等公开接口，浏览器端 JSONP 解决跨域，默认数据落在 `localStorage`。

它 **不是** 券商交易系统，**不是** 投顾产品，README 白纸黑字：**公开接口仅供个人学习参考，数据可能延迟，不作为任何投资建议**——下文会单独写免责。

**我的决策句：你只想盯估值和重仓、愿意接受「数据非官方实时」与 AGPL 协议边界，优先试 fund.cc.cd 或自部署；要完整社区、交易下单、官方客服，仍用天天基金 App 或雪球，别指望基估宝 1:1 替代。**

## 📦 基估宝是什么？

一句话：**玻璃拟态 UI 的基金看板**——添加自选基金，自动刷新估值，展开看前十重仓股占比与今日涨跌；进阶可记持仓份额、成本价、买卖流水、定投计划，并按分组与自定义排序管理。

和天天基金 App 的相似点：都看场外基金估值。差异点：基估宝 **无 App 壳、无社区、无开户**；纯 Web，可静态托管。和雪球的差异：雪球偏 **UGC 与组合社交**；基估宝偏 **个人持仓仪表盘**，README 没写「跟单」「组合广场」。和 Excel 手工表的差异：基估宝 **自动拉公开接口**，你只管代码和份额。

技术栈（README）：Next.js App Router、原生 CSS 玻璃拟态、GitHub Actions 部署 Pages；可选 Supabase 做云端备份与冲突处理；另有 npm 包 `@jigubao/cli` 供终端查价与同步自选。

### 功能特色一览

| 功能模块 | 具体表现 | 实用价值 |
|----------|----------|----------|
| 实时估值 | 输入六位代码，展示单位净值、估算净值、盘中涨跌幅 | 盘中快速扫一眼盈亏，不用开重型 App |
| 重仓追踪 | 自动拉前十重仓股，展示占比与今日涨跌，可收起/展开 | 看基金「今天被哪几只股拖着走」 |
| 持仓与交易 | 记录份额、成本价，支持买卖流水，算持仓收益与累计收益 | 把「看估值」和「我的账」放同一页 |
| 定投与分组 | 日/周/月定投计划自动生成买入；多分组 + 拖拽/规则排序 | 多账户、多策略时分组比一长列表清楚 |

### 实时估值与重仓：我的主场景

README 用法：顶部输入框填 `110022` 这类六位代码，点添加，卡片出估值；展开看重仓列表。刷新间隔在设置里调 **5–300 秒**，也可手动刷新。对我这种「午盘瞄一眼、收盘再核对」的人，价值是 **少切 App**；接口是否延迟、估算净值与最终公布净值偏差多少，README 已提醒 **不作投资依据**——**本文不编造「比 App 快 X 秒」**。

> 📷 **配图待补**：基金卡片与前十重仓展开（落盘名：real-time-fund-feature-valuation.png）

### 持仓、交易与定投

不只「看盘」：可录持有份额与成本，买卖记流水，定投按周期自动生成买入记录。实用价值是把 **估值浮动** 和 **你的实际盈亏** 绑在同一张卡片；但若你只在券商 App 里交易、从不在第三方记份额，这层功能就是负担——可以只用自选列表，不填持仓。

> 📷 **配图待补**：持仓收益与交易明细界面（落盘名：real-time-fund-feature-portfolio.png）

### 主题、导入导出与云同步

亮/暗主题一键切换；配置可导出 JSON 备份、从文件恢复。Supabase 为 **可选**：要自己建项目、跑 `/doc/supabase.sql`、配 OAuth 与 Edge Function（OCR 识图、估值排行代理等进阶能力 README 有单独章节）。不用登录时，数据只在浏览器 `localStorage`——换机或清缓存就丢，这是设计选择不是 bug。

### 命令行 @jigubao/cli

`npm install -g @jigubao/cli` 后可用 `jgb login`（Supabase 邮箱 OTP）、`jgb price <代码>`、`jgb portfolio list` 等；除登录外支持 `--json` 输出，方便和 `jq` 管道。终端党可把「扫一眼估值」塞进 cron 或 status bar，但 CLI 依赖云登录时，隐私边界要从 Supabase 政策读起。

## 🧠 核心逻辑：它为什么不一样？

天天基金、雪球的路径是 **官方 App + 自家后端 + 商业生态**；基估宝路径是 **浏览器纯前端 + JSONP/脚本注入公开源 + 本地存储**，必要时 **自托管 Next 静态产物或 Docker**，可选 Supabase 只做 **用户配置同步** 而非替你做行情中心。

三拍：前端发起跨域友好的 JSONP/注入请求 → 解析天天基金估值、东财 HTML 重仓、腾讯 Script 行情 → 渲染玻璃拟态卡片并写入 localStorage。 AGPL-3.0 意味着：若你把修改版 **作为网络服务** 提供给他人，须向用户提供对应源码——商用 SaaS 包装前先过法务，别只看「免费开源」。

GitHub Pages / fund.cc.cd 演示的是 **静态托管可行性**；Docker Hub 有 `hzm0321/real-time-fund:latest`，支持构建时或运行时注入 `NEXT_PUBLIC_*` 环境变量。数据源不是基估宝自建机房，而是 **第三方公开接口**——接口变更、反爬、字段下线都会直接打断功能，这是架构上的单点风险。

| 维度 | 基估宝（Real-time Fund） | 天天基金 App | 雪球 |

## 🧪 实测：我实际跑下来的体验

说明：撰写日依据 GitHub README 与官网文档；**未在本地完整部署 Supabase Edge Function 与 OCR 全链路**，**未测量刷新间隔的实际延迟毫秒数**。夹内笔记为空，以下「好的/不好的」来自文档边界推演与同类工具经验，不写虚构 benchmark。

### ✅ 好的方面

**1. 纯前端 + JSONP 让静态部署成立**  
GitHub Pages、fund.cc.cd 都能跑，不强制自建后端行情服务——对个人或小团队自托管友好。

**2. 功能纵深超出「只看净值」**  
持仓、流水、定投、分组、排序、导入导出在一套 UI 里，少在 Excel 与多个 App 间拷贝。

**3. 刷新频率可配置（5–300 秒）**  
比固定轮询更省请求；手动刷新按钮适合「临近收盘猛按几下」。

**4. 可选 CLI 与 `--json`**  
`jgb price` 一类命令适合脚本化提醒；和 Web 共用 Supabase 登录态时，终端与浏览器数据一致。

**5. Stars 1626 + 文档详实**  
Supabase、Docker、Edge Function 均有 README 章节，Issue 可追踪，比「只有截图没文档」的同类仓库安心。

### ❌ 不好的方面

**1. 数据延迟与准确性无官方 SLA**  
README 免责声明：公开接口、可能延迟、非投资建议。盘中估算净值与晚间公布净值不一致是常态，不能当清算依据。

**2. 公开接口依赖脆弱**  
天天基金/东财/腾讯字段或跨域策略一变，前端就要跟着改；没有商业 API 合同兜底。

**3. Supabase 云同步配置税高**  
SQL 初始化、OAuth、Edge Function、CSV 导入关联板块——不用云功能可以跳过，要用则预留半天读文档。

**4. AGPL-3.0 商用与网络服务义务**  
修改后对外提供网络服务需开源对应版本；企业内嵌或 SaaS 包装前必须读 LICENSE，不是 MIT 随便用。

**5. 无社区、无交易、无投顾**  
它解决不了「这只基金能不能买」——只能帮你看数字；决策仍在你和持牌渠道。

**6. localStorage 默认方案的换机风险**  
不登录 Supabase 时，清浏览器数据即清空自选与持仓；备份习惯要靠自己导出 JSON。

我真实会留它的场景：桌面第二屏开 fund.cc.cd，午盘看自选估值和重仓股颜色；周末导出 JSON 备份。会弃用的场景：需要在一 App 里完成申购赎回——基估宝不碰交易链路。

## 💡 怎么高效用它

### 用法 1：先用官方预览，再决定是否自托管

直接打开 https://fund.cc.cd/ 或 GitHub Pages 预览，加 3–5 只常看基金，调刷新间隔到 30–60 秒观察一天稳定性。满意再 `git clone` + `npm install` + `npm run dev` 本地跑；**不必第一天就 Docker + Supabase 全栈**。

> 📷 **配图待补**：设置里调整刷新间隔（落盘名：real-time-fund-usage-1.png）

### 用法 2：持仓与导出 JSON 当「轻量账本」

只在基估宝记份额与成本，买卖在券商 App 完成后再回来补流水；每周导出 JSON 到 NAS。比 cloud 笔记里手算公式少一步，但记得 **估值仍是估算**。

### 用法 3：CLI 做终端提醒（可选）

已配 Supabase 登录时，`jgb price 110022 --json | jq` 可接桌面通知脚本。未配云时 CLI 价值打折，别为 CLI 强行上云。

## ⚠️ 安装和使用需要注意什么？

### 免责声明（README 原文精神，必读本节）

**本项目所有数据均来自公开接口，仅供个人学习及参考使用。数据可能存在延迟，不作为任何投资建议。** 写进你的使用习惯：基估宝是 **看板工具**，不是 **决策引擎**；盈亏结算以基金公司公布净值与券商对账单为准。

### 数据源与合规

JSONP 抓公开页属于「个人学习参考」叙事；若你二次部署对外提供服务，除 AGPL 义务外，还要自己评估 **数据使用与金融信息传播** 当地法规——README 不给法律意见。

### AGPL-3.0 商用

允许使用、修改、分发；**基于本项目修改并通过网络提供服务时，须向该服务用户提供对应源代码**；衍生作品需同协议开源。二开或转载 README 要求注明出处。

### Supabase 与隐私

启用云同步时，配置数据进 Supabase 项目；Edge Function（如 OCR）可能把截图发往第三方模型（README 提及 AINX 赞助接口）。默认仅用 localStorage 时数据在浏览器，但仍会通过 JSONP 向公开行情源发起请求。

### Docker 与环境变量

`NEXT_PUBLIC_SUPABASE_URL`、`NEXT_PUBLIC_SUPABASE_ANON_KEY` 等可在构建或运行时注入；不用登录/反馈/GA 可留空。镜像：`docker pull hzm0321/real-time-fund:latest`。
