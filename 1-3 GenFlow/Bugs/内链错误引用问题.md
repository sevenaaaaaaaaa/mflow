### 三、修复手段

**核心思路**：不改内容关系（保留内链），只修格式（加超链接 + 真实标题作锚文本）。

```
Before:  { "text": "https://blogs.lovart.ai/slug - 截断描述", "marks": [] }
After:   { "text": "Sanity 中查到的真实 Title", "marks": ["lk1"] }
         + markDefs: [{ "_key": "lk1", "_type": "link", "href": "https://..." }]
```

**执行流程**：
1. 按语言拉取受影响 blog 的完整 `body`
2. 正则提取 RR 章节中 `blogs.lovart.ai/{slug}`
3. 批量 GROQ 查目标 slug → 取 `title`
4. 逐 block 构建新 Portable Text（注入 `markDefs` + `marks`）
5. Sanity `patch.set({body})` 批量写回

**分批执行**：11 批按语言，EN (1,323) → JA (72) → RU (14) → … → IT (1)

### 四、潜在风险

| 风险 | 概率 | 缓解 |
|------|------|------|
| **目标 slug 404** — URL 存在但 Sanity 中无对应 blog | 中 (~2%) | 回退用 URL 中截断的描述文本作为锚文本 |
| **patch.set 覆盖并发写入** — 其他 agent 同时修改同一 blog | 低 | 单线程串行、分语言隔离 |
| **body 数组索引漂移** — 修复后 body 长度变化影响后续查询 | 低 | 一次性拉取全量 body → 本地构建 → 一次性写回 |
| **CDN 缓存延迟** — 修复后前端不立即生效 | 中 | CDN 天然延迟，无需额外处理 |
| **大 body 写回截断** — 超大 body 的 `patch.set` 可能失败 | 中 | 已知问题：超 20KB body 用 `createOrReplace` 而非 `patch.set` |
| **Token 过期** — 长时间运行中 Sanity token 失效 | 中 | 分批执行，每批前验证 token |
