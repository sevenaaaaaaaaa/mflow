## 每篇文章的会话纪律（铁律）

| 项 | 要求 |
|---|---|
| 同篇同会话 | 一篇文章的全部槽位（2–6 张）必须同一会话连续生成 |
| 锁 seed | brief 里的 `seed` 按 slug 生成，直接使用；同一篇文章全部槽位共用 |
| 同航道 | brief 已按槽位指定航道（lane 字段），不要跨航道混跑一个会话 |
| 机位互异 | brief 已带 `camera` 字段（同篇自动轮换 6 机位），照抄即可 |
| 只换内容 | 同批内只变主题与机位，**航道 token 与调色板一字不改** |
| 内容锚点不动 | brief 带 `signals` 字段（形态来源/受众/步骤/工具）——重 roll 时保持这些内容锚点，只调构图措辞 |
| 重 roll | 不合格只改 prompt 里的 [moment]/[camera] 片段，禁止改航道与负面词 |

## 每个 chunk 的操作流

1. 打开 `batches/{wave}-{nn}.jsonl`，按顺序投喂（每条含完整 prompt + negative + seed + 尺寸）。
2. 生成后按验收卡逐张过：比例 16:9 / 四边安全 ≥8% / 层级三要素（材质+光比+点睛色）/ 航道 match / 无文字无 UI / 无过时风格元素。
3. 命名落盘：`blog-{slug}-s{槽位}-{类型}-v1.png`（brief 里已给 `filename`）。
4. 上传 CDN 后回写对应文章正文的 image 槽位（`convert.js` 侧按 slug+slot 对位）。
5. 在下表进度追踪打勾；一个 chunk 未过验收不开下一个（同航道风格才不会漂）。

## QC 与返工

- 每 chunk 交付前自查 + 抽查 20%；BLOCK 项：出现文字/数字、假 UI、紫蓝渐变、玻璃拟态、>3 元素拼贴、面部畸形。
- 返工只允许动 [moment]/[camera]，动过航道 token 的整批作废重跑。
- 全部通过后在 `manifest.json` 登记实际产出文件与 QC 日期（对齐 Hero 批次的 QC 台账习惯）。
