### 三、修复手段

| 手段 | 适用场景 | 执行次数 |
|------|----------|----------|
| **Sanity delete** — 去重，保留最佳版本 | 同 slug 双/三文档 | 283 + 11 = 294 次 |
| **Sanity patch bodyJson** — 解析→修改→重序列化 | hero title/image/badge/proof-block/FAQ | ~1,500 次 |
| **Tools→Features bodyJson 复制** | 同 slug 恢复完整内容 | 260 次 |
| **模板生成 11 段 bodyJson** | 无 tools 对应的 features 瘦版 | 294 次 |
| **文案差异化脚本** — badge/描述/bento/FAQ/CTA 改写 | Tools↔Features 去重 | 240 次 |
| **Sanity patch SEO** — seo.title + seo.description | 非 EN slug 泄漏 | 189 次 |
| **Landing 13 段 bodyJson 重写** | 3 个 meta 页面 | 3 次 |

### 四、潜在风险

| 风险 | 严重度 | 说明 |
|------|--------|------|
| **批量 patch 的 bodyJson 未逐篇人工审核** | 🟡 | 260 复用 + 294 模板 + 240 差异化，共 ~800 页机器生成内容 |
| **模板生成页面的内容通用性强** | 🟡 | 294 页 features 用的是同一套文案模板，SEO 可能被判低质 |
| **CDN 缓存未刷新** | 🟡 | Sanity 已正确但前端可能数小时内仍显旧版 |
| **多语言版本未同步** | 🟠 | 只修了 EN；ko/pt/ru/zh-TW/ja 等仍可能是旧版/瘦版 |
| **22 个 Skeleton 页面未修复** | 🟠 | Tools 里仍有 22 个 <8 段的残页 |
| **备份仅本地 `/tmp/`** | 🟡 | 重启后可能丢失 |
