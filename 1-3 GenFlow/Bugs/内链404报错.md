## 会话汇总：Blog 内部链接 404 问题

### 一、质量问题（单一根因，系统级扩散）

**根因**：Blog body 的 Portable Text link marks 使用绝对 EN URL `https://www.lovart.ai/blog/slug`（无语言前缀），而非语言感知路径。

**表现**：
- 用户在 `/zh/blog/flora-ai-review` 点击"遛狗师品牌套件"→ 跳 `/zh/blog/brand-kit-dog-walker-lovart` → **404**
- 前端按浏览器语言重定向 `/blog/slug` → `/zh/blog/slug`，目标语言版本缺失即 404
- 影响范围：扫描 8,333 篇，6,192 篇（74%）受影响，12,903 个链接异常

**语言缺失验证**（以 `brand-kit-dog-walker-lovart` 为例）：EN=200, ZH=404, JA=200, DE=200, FR=200, PT=404, KO=404, RU=404, ZH-TW=200

### 二、排查进度

| 阶段 | 状态 | 结果 |
|------|------|------|
| 根因定位 | ✅ | 绝对 EN URL → 语言重定向 → 404 |
| 全量扫描 | ✅ | 8,333 篇扫描完，6,192 篇受影响 |
| 批量修复 | ✅ | 6,192/6,192 篇 patch 完成 |
| Sanity 数据验证 | ✅ | 10/10 spot check 通过 |
| CDN 线上验证 | ⏳ | 缓存未刷新，待几小时后复测 |

### 三、修复手段

1. **转换规则**：`https://www.lovart.ai/blog/slug` → `/blog/slug`（相对路径，前端按当前语言解析）
2. **批量脚本**：`fix-blog-internal-links-full.py`，支持断点续扫（每 100 篇写进度文件）
3. **安全护栏**：
   - 只改 `_type=="link"` 且 href 含 `lovart.ai/blog/` 且无语言前缀的 marks
   - 语言前缀 URL（`/zh/blog/`、`lovart.ai/ja/blog/`）和外部链接（google.com）不动
   - 相对路径（`/blog/xxx`）不动 → 幂等
4. **逻辑验证**：17 项 inline 单元测试全过（覆盖嵌套结构、多链接 span、trailing slash、幂等性）

### 四、潜在风险

1. **CDN 缓存滞后**：Sanity 已改，但线上 CDN 可能几小时才刷新。用户现在访问仍可能看到旧 404。
2. **目标 slug 本身不存在**：转为相对路径只解决"语言前缀"问题。若目标 blog 在所有语言都不存在（从未发布/已删），转相对路径后仍 404。
3. **ES/IT 语言混入**：数据中出现 `es`/`it` 链接，但 AGENTS.md 语言列表未列这两语。修复逻辑已覆盖，但需确认这两语是否正式上线。
4. **其他内容类型同病**：compositePage、landing page、tool page 的 body 可能也有绝对 EN URL 内链，本次只修了 `blog` type。
5. **无回滚预案**：patch 直接覆盖 body，未备份原 body。若需回退需从 Sanity 历史版本恢复。

### 五、还能做

1. **CDN 刷新后线上复测**：实际点击 `flora-ai-review` ZH 内链，确认跳转正常。
2. **目标 slug 存在性审计**：列出所有被引用的 slug，查哪些在任何语言都不存在 → 要么补发、要么移除死链。
3. **扩展修复到其他 type**：compositePage / landing page 跑同逻辑扫描。
4. **Preflight 门禁**：新发布 blog 时强制检查 body 内链为相对路径（写入 lovart-content-quality-gates 或 signal-writer 验收）。
5. **死链监控**：定期 GROQ 查 `body` 含 `lovart.ai/blog/` 绝对 URL 的文档，防回归。
6. **备份原 body**：若未来需回滚，建议先 export 受影响文档的 body 到 `Output/QA-Memo/` 再 patch。
