# Lovart 产出路由规则 — 最终版

> **核心原则**：每个 skill 写入文件时必须明确判断该产物是「知识资产」还是「过程缓存」。知识资产 → MindRe；过程缓存 → Local Dev。不允许第三种情况。

---

## 路由决策树

```
产出物是「定义/报告/结论/策略」吗？
├── 是 → 有人类长期参考价值吗？
│   ├── 是 → MindRe 1-2 Insight（知识资产）
│   └── 否 → Local Dev Output（一次性报告草稿/调试输出）
└── 否 → 是运行过程产物吗？
    ├── 拉取缓存/原始数据快照 → Local Dev Output/
    ├── 生成的文章/页面 JSON → Local Dev Output/
    ├── sitemap/robots/llms 生成物 → Local Dev Output/
    ├── 脚本/配置/规则定义 → MindRe 1-1 Harness 或 1-4 Dev
    └── 日志/临时文件 → Local Dev Temp/ 或 Logs/
```

## 三、环境变量

所有 skill 必须使用环境变量引用路径，禁止硬编码：

```bash
# 知识资产根路径
LOVART_INSIGHT_ROOT="$HOME/Library/Mobile Documents/iCloud~md~obsidian/Documents/MindRe/1-Project/Lovart MFlow/1-2 Insight"

# 过程缓存根路径
LOVART_LOCAL_DEV_ROOT="$HOME/Lovart Local Dev"
LOVART_OUTPUT_ROOT="$LOVART_LOCAL_DEV_ROOT/Output"

# 源码根路径
LOVART_HARNESS_ROOT="$HOME/Library/Mobile Documents/iCloud~md~obsidian/Documents/MindRe/1-Project/Lovart MFlow/1-1 Harness"
LOVART_DEV_ROOT="$HOME/Library/Mobile Documents/iCloud~md~obsidian/Documents/MindRe/1-Project/Lovart MFlow/1-4 Dev"
```

## 四、Skill 作者自检清单

每个产出文件的 skill 必须在写入前回答：

1. **谁会读？** → 人类决策者 → MindRe；脚本/agent → Local Dev
2. **多久后还有用？** → 永久/季度/年度 → MindRe；发布后即过期 → Local Dev
3. **是结论还是中间产物？** → 分析结论/策略建议 → MindRe；原始数据/缓存 → Local Dev
4. **出问题时需要回溯吗？** → 是（如月报环比） → MindRe；否（如 sitemap 旧版） → Local Dev

**最终分支**：
- 4 个问题任一答「永久/人类/结论/需回溯」 → MindRe 1-2 Insight
- 全部答「临时/机器/中间/不需」 → Local Dev Output

## 五、违规处理

- 新产出的报告类文件出现在 `$LOVART_LOCAL_DEV_ROOT/Output/SEO-Reports/` → **立即标记为路由错误，复制到 MindRe 对应位置，Local Dev 副本保留 7 天后删除**
- Skill 中硬编码了 `Output/SEO-Reports` 路径 → **patch 为该 skill 的 MindRe 对应路径**
- 报告同时出现在两个位置 → **以 MindRe 版本为准，标记 Local Dev 副本为「待清理」**
