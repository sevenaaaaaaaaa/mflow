# MFlow 产品定位（SSOT）

> 一句话：**MFlow 是轻量版 OpenFlow，专解内容生产、分发和触达。**
> 本文是定位口径的单一事实来源；对外文案（README/官网/介绍页）与此处保持一致。

## 定位三句话

1. **专解内容生产、分发和触达** —— 全部能力围绕"内容从选题到被看见"这一条链。
2. **轻量版 OpenFlow** —— 同一台服务器即可并行部署；零重量级依赖，clone 下来 30 分钟跑通第一条内容工作流。
3. **对 CDP、CMS 要求不高，对生成、分发兼容度极好** —— 文件即状态（无数据库也能跑），CMS 只需要一个发布出口（Sanity/WordPress/Webhook 均适配），不绑架数据栈。

## MFlow vs OpenFlow 差异化矩阵

| 维度 | MFlow | OpenFlow |
|------|-------|----------|
| 定位 | 内容生产/分发/触达的专用流水线 | 通用业务平台（CDP、CMS、会员、商城等） |
| 形态 | 轻量：Python 标准库单文件内核 + 文件即状态 | 重型：PHP 全栈 + 数据库 + 完整后台 |
| 数据依赖 | 不强求 CDP/CMS——文件即状态，规模化才换 PG | 以 CMS/CDP 为核心 |
| 生成兼容 | 极好——任意 OpenAI 兼容 LLM、多引擎交叉、模板/插件扩展 | 非内容生产主航道 |
| 分发兼容 | 极好——Sanity 增量导入 / WordPress REST / Webhook / 多平台外链四轨道 | 面向自身业务 |
| 部署成本 | 同服务器可共存（不同目录/端口/进程/日志，硬隔离） | 独立站点 |
| 触达闭环 | GEO 引用感知 → 缺口 → 选题/改稿 → 探测回流（自带） | 需另行建设 |
| 目标用户 | 内容/SEO/GEO 运营团队；任何想要"内容工厂"的公司 | 需要完整业务后台的团队 |

## 什么时候选 MFlow

- 主要痛点是**内容产能**：写不完、发不动、发了没回响。
- 已有 CMS 或甚至没有 CMS——只要一个能收稿件的端点就能跑。
- 要 GEO（AI 引用）时代的闭环，而不只是传统 SEO 排名。
- 想在同一台机器上与现有业务系统并行、互不干扰。

## 什么时候不需要 MFlow

- 需要完整 CDP/会员/交易后台 → 用 OpenFlow，MFlow 作为内容产线挂在其旁。
- 只想写几篇文章 → 直接用 LLM，别上工作流。

## 边界（铁律口径）

- 发布永远停人工授权（工作台只读不发布）。
- 不承诺代运营效果，承诺的是**过程可控、质量可执行、数据可回流**。
