## 👤 测评人背景

我有一台长期插着充电线的旧安卓——跑自动化、收验证码、偶尔当测试机。以前用 AirDroid 在电脑浏览器里管文件和通知，免费版广告和云中转让我不舒服；scrcpy 镜像很稳，但不想要「只能看屏幕」；KDE Connect、Blip 传文件够用，却管不了短信和通话记录。PlainApp 进清单，是因为 AGPL 开源、Stars 6425、叙事是 **同 Wi-Fi 下浏览器变管理中枢，TLS + XChaCha20，不经厂商云**。下面按仓库 README 与夹内笔记拆，远程场景按「需自配 VPN」写边界，不夸大「随时随地」。

---

## 🎯 先说结论

PlainApp 把安卓手机变成 **局域网内的 Web 管理端**：电脑浏览器打开 PWA，在同 Wi-Fi 下管理文件、短信、通话、屏幕镜像、通知等；内置笔记、RSS 播放器、DLNA 等附加模块。它是 **AirDroid 的开源替代取向**，核心卖点是 **加密直连、无云中转**——流量在你家路由与手机之间，不经 PlainHub 服务器存盘（以项目隐私叙事为准）。

门槛也真实：必须 **同一 Wi-Fi**；首次访问常见 **自签名证书警告**；国产 ROM **杀后台** 会导致断连；与某些 **VPN 冲突**；Android 9+。**跨网远程** 官方口径是 **自己搭 VPN** 进局域网，不是一键公网穿透。

**我的决策句：你主要在同一 Wi-Fi 管一台安卓、接受 AGPL 与自签证书折腾，优先试 PlainApp；要官方云账号即连、或 iOS 对端，不建议把它当 AirDroid 1:1 替代品。**

## 📦 PlainApp 是什么？

一句话：**安卓端装 App，局域网浏览器开 PWA，加密管理手机**——文件浏览、短信收发、通话记录、投屏镜像、通知同步，外加笔记/RSS/DLNA 等「顺便做掉」的模块。

和 AirDroid 的相似点：都是「电脑浏览器管手机」。差异点：PlainApp **不开云中转**（配置与流量路径在你侧），协议栈强调 TLS + XChaCha20；AirDroid 免费版常绑云账号与广告。和 scrcpy 的差异：PlainApp 给 **结构化 Web 面板**（短信、文件树），不只是镜像；和 KDE Connect / Blip 的差异：后者偏桌面生态文件同步，PlainApp 偏 **浏览器全能控制台**。

## 🧠 核心逻辑：它为什么不一样？

AirDroid 类产品的隐含路径往往是 **手机 → 厂商云 → 浏览器**；PlainApp 路径是 **手机 ↔ 局域网 ↔ 浏览器**，加密在链路上，PlainHub 不当中转存储（以项目说明为准）。

三拍：手机端常驻本地 HTTPS 服务 → 浏览器 PWA 用配对/证书建立信任 → 各功能模块走同一 WebSocket/HTTP 通道。 AGPL-3.0 意味着二次分发与网络服务修改有义务边界——商用内嵌前先读 LICENSE，别只看「免费」。

远程访问没有魔法：**官方口径是自配 VPN 打进 home LAN**，不是内置 frp。这和「扫码即连公网」的竞品预期要分开。

## ⚔️ PlainApp 和 AirDroid、scrcpy、KDE Connect 有什么区别？

| 维度 | PlainApp | AirDroid | scrcpy | KDE Connect / Blip |
|------|----------|----------|--------|---------------------|
| 开源 | AGPL-3.0 | 闭源 | 开源 | 开源 |
| 云中转 | 无（LAN 为主） | 免费版常经云 | 无 | 无 |
| 浏览器控制台 | PWA 全能面板 | 有 | 无（仅镜像） | 无/弱 |
| 短信/通话 | 支持 | 支持（视版本） | 不支持 | 一般不支持 |
| 镜像 | 有 | 有 | 极强 | 无 |
| 远程 | 需自配 VPN | 官方云远程 | USB/Wi-Fi 调试 | 视实现 |
| 协议 | TLS + XChaCha20 | 厂商方案 | adb | 各生态 |

选型句：要 **开源 LAN 全能 Web 控** → PlainApp；要 **零配置云远程** → AirDroid 类商业方案；要 **最低延迟镜像** → scrcpy；要 **只传文件且已在 KDE 生态** → Connect/Blip 更轻。

## 🧪 实测：我实际跑下来的体验

说明：功能边界来自 GitHub README 与官网；**未在撰写日实测跨网 VPN 与 DLNA 全链路，不写传输速度数字。**

### ✅ 好的方面

**1. 无云中转叙事对隐私敏感场景友好**  
验证码机、内测包不想过第三方云，LAN 直连心理负担小。

**2. 一个 PWA 覆盖文件+短信+镜像**  
少装多个单点工具，浏览器书签即入口。

**3. Stars 6425 + 活跃开源社区信号**  
Issue 与 PR 可查，比小众脚本安心。

**4. 附加模块对「旧机再利用」划算**  
笔记/RSS/DLNA 让常年插电的备用机更像小服务器。

### ❌ 不好的方面

**1. 自签名证书警告吓退第一次使用者**  
必须理解「信任此证书」含义；团队推广要写一页 SOP。

**2. 国产 ROM 杀后台断连**  
锁后台、关电池优化、允许自启动——三步缺一步就「浏览器打不开」。

**3. 与 VPN 冲突**  
全局 VPN 常改路由，PlainApp 的 LAN 发现会失败；要分流或暂时关 VPN。

**4. 远程非开箱即用**  
没 VPN 就没「外面连回家」；别期待 AirDroid 式扫码公网。

**5. AGPL 商用需谨慎**  
网络服务修改有开源义务，企业内网要先过法务。

**6. 镜像体验通常不如 scrcpy 专精**  
要录屏演示高质量，我仍会 adb + scrcpy 补位。

我真实会留它的场景：测试机放机房，我在笔记本浏览器收短信验证码、拖 APK，不用起身。会弃用的场景：出差酒店 Wi-Fi 想管家里手机——没提前配 VPN 就是干瞪眼。

## 💡 怎么高效用它

### 用法 1：专用 Wi-Fi + 固定浏览器配置文件

给 PlainApp 单独 Chrome Profile，证书信任一次长期有效；手机端固定 IP 或 DHCP 保留，书签写 `https://192.168.x.x:端口`。

> 📷 **配图待补**：浏览器信任证书步骤（落盘名：plainapp-usage-1.png）

### 用法 2：验证码机 + 文件仓

旧机只插 Wi-Fi、关移动数据；短信与 2FA 全在浏览器看；大文件导出走 Web 下载，避免云盘中转。

### 用法 3：与 scrcpy 互补

PlainApp 管短信和文件树；要精细触控演示再开 scrcpy。两者同 LAN，不互斥。

## ⚠️ 注意事项：安装和使用

### 同 Wi-Fi 是硬前提

访客网络、客户隔离 Wi-Fi、手机热点给电脑但不在同一 L2 网段，都可能连不上——先 ping 再怪 App。

### 自签名证书

首次访问浏览器会警告；生产环境可考虑内网 CA 签发，降低团队培训成本。

### Android 9+ 与后台

低于 9 不在支持范围；后台被杀见上文，MIUI/ColorOS 用户预留十分钟做白名单。

### 远程访问

官方：**自配 VPN**（WireGuard/OpenVPN 等）连回家 LAN 后再开 PWA。不要把端口裸暴露公网——没有云不代表没有风险。

### AGPL-3.0

修改网络服务并对外提供时，有源码公开义务；内网自用也要读 LICENSE 边界。

## 周更里我会怎么用

周一：旧安卓开机，PlainApp 服务启动，浏览器书签收 overnight 短信与 cron 日志。验证码短信在 Web 端复制粘贴，比反复解锁摸手机省注意力。  
周三：从 Web 端拖本周 build 的 APK 进手机，镜像点两下回归测试；若镜像卡顿，我会切 scrcpy 只看触控，文件仍走 PlainApp。  
周五：DLNA 推一段播客到客厅音箱——能用但非刚需，失败就换回专门播放器。  

和 AirDroid 分工：要在外网 café 零配置连手机，我仍用商业云方案；在家 LAN PlainApp 足够。和 scrcpy 分工：文件短信 PlainApp，精细演示 scrcpy。VPN 我只在 WireGuard 回家后才开 PWA，从不端口转发裸奔。

备用机策略：长期插电的那台只连 home SSID，关闭移动数据，减少意外流量外泄；浏览器端单独 Profile 存证书信任，不和日常冲浪混用。团队若推广，我会先发一页「信任自签证书 + 后台白名单」截图 SOP，比口头解释少踩坑。笔记/RSS 模块我偶尔用，不当作装 PlainApp 的理由——理由永远是 LAN 文件与短信。若路由器开了 AP 隔离（访客网络），PlainApp 会直接失效，排查时先查 SSID 是否同一网段，再查 App 是否在跑。出差前我会确认 WireGuard 配置仍有效，否则宁可不带「远程管手机」的幻想。AGPL 协议我也贴在团队 wiki：内网自用和对外 SaaS 化是两条法务路径，别混谈。镜像录屏我仍交给 scrcpy，PlainApp 只负责「不用拔线就能传文件看短信」——分工清楚，期望才不会错位。

> **怎么选：** 主要 **同一 Wi-Fi 管安卓**、重视 **无云中转与 AGPL 可审计** 的人，**优先**装 PlainApp 并接受证书与后台白名单；要 **官方一键远程**、**iOS 对端** 或 **不愿碰自签证书**，**不建议**拿它硬替 AirDroid——体验预期不对齐。
