## 测评人背景

做了十几年市场营销，录屏是我日常工作的「刚需」——产品演示、客户 walkthrough、团队培训、社媒内容、bug 复现录屏……用过 CleanShot X、Loom、Screen Studio、OBS 几乎所有主流录屏工具。Loom 曾经是我的主力，但 2024 年涨价后 $15/月只能存 25 个视频的限制让人很不爽。去年关注到 Cap，一个开源 Loom 替代品，17.2K Stars、Rust 写的核心引擎、秒速分享链接，花了一周把它从安装到日常使用跑通，下面是完整体验。

## 先说结论

Cap 是开源的轻量级屏幕录制与即时分享工具，核心卖点是**「录完即分享」**——点录制、选区域、录完自动上传生成分享链接，体验和 Loom 几乎一致，但完全开源免费、数据你自己控制。

**优点**：Rust 核心性能好、录屏画质流畅、分享体验丝滑、可自建服务端、开源协议活跃。**缺点**：编辑功能偏弱（只能裁剪）、Mac 版比 Windows 版稳定、自建服务端需要一定运维能力、功能深度不如 CleanShot X 这种付费重型工具。

**一句话总结：如果你在用 Loom 且厌倦了涨价和限制，Cap 是你目前能找到的最好的开源替代方案。**

## 核心逻辑：Rust 引擎 + 现代技术栈，快在哪

### 1. Rust 录屏引擎

Cap 的核心录屏引擎用 Rust 编写，这是它和大多数 Electron 录屏工具最大的区别。Rust 带来的优势：
- **低资源占用**：录制 4K 屏幕时 CPU 占用明显低于 Loom 和 OBS
- **高帧率支持**：支持 60fps 甚至更高帧率的流畅录制
- **跨平台一致性**：Windows、macOS、Linux 共享同一套核心代码

底层使用了各平台的原生屏幕捕获 API（macOS ScreenCaptureKit、Windows DXGI、Linux PipeWire），保证了兼容性和性能。

### 2. 秒级分享

Cap 的分享逻辑是它的灵魂：录制完成 → 自动编码（H.264/H.265）→ 上传到 Cap 服务器或自建服务器 → 生成短链接 → 一键复制。整个流程通常只需要 2-5 秒（取决于视频长度和网速），对方打开链接就能在线观看，不需要下载文件、不需要安装任何东西。这个体验和 Loom 是完全一致的。

### 3. 自建服务端

Cap 的另一个核心能力是**你可以自己部署服务端**。官方提供了完整的 Docker Compose 配置，包含 Next.js 前端、后端 API、PostgreSQL 数据库、S3 兼容存储（支持 MinIO、Cloudflare R2、AWS S3）。这意味着你的录屏视频可以完全存储在自己的服务器上，数据不外传。

## 实际体验：好在哪，坑在哪

### 好的方面

**1. 安装体验极简**

Mac 上就是拖到 Applications，Windows 上跑安装包。没有复杂的依赖安装、没有环境配置、不用碰命令行。打开就能录，这对非技术用户来说是巨大的加分项。

**2. 录屏画质和性能令人满意**

我用 Cap 录了以下场景的实际测试：
- 全屏 4K 录制产品 Demo（30fps，3 分钟）：文件大小约 45MB，画质清晰，无掉帧
- 区域录制 UI 交互演示（1080p，60fps，1 分钟）：文件约 15MB，鼠标轨迹顺滑
- 摄像头 + 屏幕画中画模式（720p + 1080p）：合成的画面自然，摄像头位置可拖拽

和 Loom 对比，同场景下 Cap 的文件体积略大 10-15%，但画质主观感受没有差距。和 CleanShot X 比，Cap 的编码优化没那么极致，但在日常使用中完全够用。

**3. 分享体验非常丝滑**

录完自动弹出分享面板，视频已上传，链接已复制到剪贴板。整个过程 3-5 秒完成，和 Loom 的体验几乎无差别。而且还多了几个有用的功能：
- **查看次数统计**：每个视频能看到被观看了多少次
- **评论功能**：观看者可以在视频时间轴上留言
- **密码保护**：给分享链接设置密码（敏感内容很有用）
- **过期时间**：设置分享链接自动失效的时间

**4. 自建服务端对团队友好**

我给团队搭了一个 Cap 自建实例（Docker Compose + Cloudflare R2 做存储），三个人的小团队日常录制产品演示和客户培训视频。好处：数据完全在团队控制范围内、无视频数量和时长限制、分享链接域名用自己的。部署复杂度中等——如果对 Docker 和 S3 兼容存储有了解，一个下午能搞定。官方文档有完整指引。

**5. 开源生态活跃**

17.2K Stars、AGPL-3.0 协议。社区维护积极，Issues 和 PR 处理及时。而且值得提的是——Cap 有一个活跃的 Discord 社区，开发者响应很快。

### 不好的方面

**1. 编辑功能很基础**

目前 Cap 的编辑能力仅限于裁剪开头和结尾。除此之外，没有裁剪中间段落、没有字幕添加、没有标注工具。对比 CleanShot X 的箭头/方框/文字标注、Screen Studio 的自动缩放和鼠标强调效果，Cap 的编辑能力确实薄弱。如果你经常需要在录制后进行标注和强调，Cap 目前还替代不了那些工具。好消息是，编辑功能在 Roadmap 上。

**2. Mac 版比 Windows 版更稳定**

这是我一周使用下来最大的感受。Mac 版的 Cap 非常稳定，一周零崩溃；Windows 版我遇到了 3 次录制中途无声的问题（重启解决），以及 1 次分享链接生成失败。社区 Issues 里也能看到 Windows 用户的类似反馈。Mac 用户目前体验更佳。

**3. 自建服务端需要运维能力**

虽然 Docker Compose 降低了部署门槛，但如果你对以下概念不熟悉——DNS 配置、HTTPS 证书、S3 对象存储、数据库备份——自建 Cap 会是一个不小的挑战。官方未来可能会提供托管服务（Cap Cloud），但目前还在内测。

**4. 摄像头画中画的尺寸和位置调整不够灵活**

Cap 支持录制时叠加摄像头画面（画中画），但只能选择几个预设位置（四角），不能自由拖拽和调整大小比例。对比 Loom 的圆形摄像头裁剪和位置自由拖拽，Cap 在这个细节上还有提升空间。

**5. 缺失系统音频录制**

Cap 目前主要录制「麦克风音频 + 屏幕画面」。如果你需要录制「系统音频」（比如录制正在播放的视频声音、会议声音），需要额外配置虚拟音频路由（如 BlackHole）。Loom 和 CleanShot X 在这方面处理得更好——它们内置了系统音频捕获。

## 高效用法：把 Cap 用到极致

### 1. 客户沟通的「异步演示」神器

这是我使用 Cap 最多的场景：客户问「这个功能怎么用」，以前要安排会议、共享屏幕、一边操作一边讲，20 分钟起。现在直接录一段 3 分钟的 Cap 视频，操作给客户看并解说明白，对方有空再看。**异步沟通效率比同步会议高 10 倍。**

### 2. 搭配 Lovart 做品牌化录屏

Cap 分享页面的 UI 本身比较简洁，但如果你想让录屏内容更有品牌感，搭配 Lovart 做录屏封面和品牌水印：在 Cap 录制前打开一个自定义的背景或桌面壁纸（Lovart 的 Brand Kit 生成品牌桌面），录制完成后用 Cap 分享，同时在 Lovart 里做一张配套的封面图，发送链接时附带品牌封面，整体观感更专业。

### 3. 团队 SOP 视频化

把团队的重复性操作做成 Cap 录制 SOP 视频库：新员工入职录制「系统账号注册」「报销流程」「内部工具使用」、客户上手录制「产品初始化」「常见操作流程」、跨部门协作录制「提需求标准流程」「报表查看方法」。所有视频存在自建 Cap 服务器上，按频道分类，团队随时查阅。比写文档快、比开会省时间。

### 4. 与 LibTV 组合做教学视频

如果你的内容需要超出「录屏」的范畴——比如加转场、特效、片头片尾、专业字幕——可以把 Cap 录制的素材导入 LibTV 做后期处理。Cap 录制操作过程 → 导入 LibTV → 加片头片尾 → 加标注动画 → 加字幕 → 渲染输出 → 发布到各平台。Cap 负责快速记录，LibTV 负责专业后期，分工明确。

### 5. 为开源项目做贡献：嵌入产品 Demo

如果你有自己的产品或者是开发者，Cap 的分享链接可以嵌入到文档里。用户点击就能看操作演示，不需要消耗你自己的服务器带宽，比自己做视频托管省心。

## 适合谁 / 不适合谁

### 适合

- **Loom 用户想省钱**：完全免费替代，体验高度一致
- **产品经理 / 设计师**：快速录制产品演示、设计走查、反馈沟通
- **远程团队**：异步沟通神器，比写文档快、比开会省时间
- **客服 / 技术支持**：录制操作教程发给客户，一次录制反复使用
- **开发者**：录制 bug 复现步骤，比文字描述直观 100 倍
- **隐私敏感用户**：自建服务端，数据不外传
- **开源爱好者**：AGPL-3.0 开源，技术栈现代（Rust/TypeScript）

### 不适合

- **需要重度编辑的用户**：编辑功能只有裁剪，标注、字幕、特效等需要其他工具
- **Windows 重型用户**：Mac 版体验更成熟，Windows 版偶有问题
- **需要极致画质的专业录屏**：如果你做的是付费课程录制，OBS 加手动编码更可控
- **纯小白且需要自建**：自建服务器有运维门槛（但用官方托管可以规避）
- **需要录制系统音频**：需要额外配置虚拟音频路由，不如 Loom 方便
