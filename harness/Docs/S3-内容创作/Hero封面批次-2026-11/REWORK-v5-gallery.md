# 返工报告 v5 · gallery 模块结构性修正 · 2026-11-04

> 触发：核实真实数据结构时发现 v2–v4 的 gallery 方案建立在错误假设上。
> 数据源：`dev/scripts/gallery-ledger.json`（全部 87 个 hero-gallery 文档实测台账）

## 一、发现的三个结构性错误

### 错误 1：瓦片字段与数量搞错

| | 原方案假设 | 实测真实情况 |
|---|---|---|
| 字段名 | 只有 `toolTiles` | **两种**：`gallery` 与 `toolTiles` |
| 瓦片数 | 固定 6 | **12 瓦（`gallery`）50 页 / 6 瓦 8 页 / 4 瓦 11 页** |
| 覆盖页面 | 60 | 69 唯一页面（87 文档折叠多语言） |

依据：`gallery-ledger.json` 实测 `{('gallery',12): 50, ('toolTiles',6): 8, ('toolTiles',4): 11}`。

### 错误 2：瓦片语义搞反（最严重）

- **12 瓦的 `gallery` 是行业维度**：商旅出行 / 国潮插画 / 极简商务 / 食品餐饮 / 科技数码 / 时尚美妆 / 教育培训 / 医疗健康 / 房地产 / 电商零售 / 文化创意 / 金融保险
- **6 瓦的 `toolTiles` 才是工具维度**：产品图 / 视频广告 / 付费创意 / 品牌套件 / 社媒贴 / 邮件头

原方案把 G-PRT / G-SOC / G-ECO / G-CMP 四套（服务 zh-topic 页 = 12 瓦行业维度）按"工具维度"设计，**维度错误**。

### 错误 3：漏了 media 主图

58/69 个 gallery 页除瓦片外还有一张独立 `media` 主图（16:10），原方案完全未计入。

即 logo 设计页与海报设计页的 12 个行业瓦片**完全相同**，且内容是占位图。这是站内现存最明显的视觉缺陷，本批次会一并修复。

## 四、新增的关键工艺约束（解决"生成必乱码"）

**含排版语义的品类**（poster / banner / menu / brochure / packaging / video-thumbnail / social-media / product-detail / ppt / resume / data-story）本身必须表达文字层级，但图内又不能有可读字符——否则生成必乱码。

解决办法：强制声明
> `all type is suggested only by abstract grey bars and shape blocks, never legible characters, no readable words anywhere, no screens, no UI windows`

已写入全部 11 个含排版品类，共 132 条瓦片。QC 对此设置了硬性检查（缺声明直接 BLOCK）。

12 瓦比 6 瓦更易雷同，因此配置 12 种互斥机位，每瓦不同：

| # | 机位 |

| 4 | 正俯拍平铺 |
| 5 | 低角度微仰 |
| 6 | 干净侧面轮廓 |
| 7 | 偏心 + 一侧大留白 |
| 8 | 叠一张次要纸张在后方 |
| 9 | 出血跑出画面 |
| 10 | 大片平静留白中的小主体 |
| 11 | 明确对角线轴摆放 |
| 12 | 前景软边切入下角形成层次 |

QC 新增**机位互异检查**：同套内机位重复直接报错。

## 八、剩余风险

1. **262 张是纯图像工作量**，建议按 `D1(18) → D2 单品类试跑(12) → 全量(216) → D3/D4(28)` 分批，先验证一个品类的 12 行业是否真能拉开差异。
2. **12 行业差异化**是本批次最大难点：若某品类的 12 行业出图仍偏同质，需加大配色/材质权重，或改为每品类只做 6 个主力行业（可降到 108 张）。
3. **含排版的 11 个品类**（132 张）风险最高——"抽象灰色条块"能否稳定表达排版层级，需首张验证。
4. **media 主图与瓦片的关系**需确认：主图应是品类总览，若设计要求主图与首瓦一致，需二次调整。
