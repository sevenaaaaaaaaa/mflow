# 代理机构操作手册：在 Lovart 中管理 10 多个客户品牌而不手忙脚乱

[图片 1 占位符 — 角色场景]

每个成长中的代理机构都会遇到这样一个时刻：你手头有第 8 个客户，每个品牌都有自己的调色板、字体、语气和素材库，而团队中有人刚刚把客户 A 的品牌蓝色用在了客户 B 的 Instagram 图片上。

这不是设计问题。这是运营问题。

管理多个客户品牌是代理机构利润率的无声杀手。每次上下文切换会浪费 23 分钟的生产时间（加州大学欧文分校）。每次在 Slack、Google Drive 和电子邮件线程中寻找品牌素材都会消耗可计费工时。每次“等等，我们用的是哪个版本的 logo？”都会侵蚀客户的信任。

Lovart 从结构上解决了这个问题——不是通过功能清单，而是通过一个为多品牌现实而构建的架构。以下是操作手册。

## 多客户架构

[图片 2 占位符 — 概念图]

Lovart 中的核心单元是**工作区**。把它想象成一个完全隔离的环境——它有自己的品牌工具包、自己的设计历史、自己的素材库、自己的团队权限。

以下是成功的代理机构如何构建他们的 Lovart 实例：

```
代理机构根目录
├── 工作区：客户 A（金融科技）
│   ├── 品牌工具包：Logo、调色板、字体、图标集
│   ├── 项目：Q4 社交媒体活动
│   ├── 项目：网站刷新
│   └── 团队：客户经理 + 2 名设计师
├── 工作区：客户 B（D2C 电商）
│   ├── 品牌工具包：Logo 套件、产品摄影风格
│   ├── 项目：BFCM 2026
│   ├── 项目：电子邮件模板
│   └── 团队：客户经理 + 1 名设计师
├── 工作区：客户 C（SaaS）
│   └── ...
└── 工作区：内部 / 新业务
    └── 推介文稿、代理机构品牌、方案工作
```

### 为什么这很重要

每个工作区都是一道防火墙。当设计师在客户 A 的工作区内输入“@commands use-brand”时，Lovart 只会从客户 A 的品牌工具包中提取内容。AI 不可能意外地应用错误的品牌。这不是一个建议——这是在架构层面强制执行的。

使用 Team 计划（每月 49 美元）的代理机构可以获得无限个工作区。Enterprise 计划（每月 99–149 美元）增加了审计日志、每个工作区的使用分析以及 SSO 集成，这样客户工作区甚至可以包含具有精细权限的客户方团队成员。

## 在 15 分钟内设置一个客户品牌

以下是我们为每个新客户推荐的入职流程：

### 第 1–5 分钟：品牌工具包导入

上传基本要素：
- 主要和次要 logo（SVG、PNG 或 AI 格式）
- 品牌调色板（十六进制代码或从上传的素材中提取——Lovart 可从任何图像中自动检测颜色）
- 字体（上传���体文件或从 Google Fonts 中选择）
- 任何现有的设计模板或示例作品以供参考

Lovart 的品牌工具包会处理这些内容并构建一个内部品牌模型。现在 AI 理解了对于这个客户来说什么是“符合品牌调性”。

### 第 5–10 分钟：风格指南快照

使用 ChatCanvas 生成一页的品牌摘要。提示词：

> “为[客户名称]生成一页品牌风格指南封面，使用他们的品牌调色板和 logo。包含 H1、H2、正文大小的字体样本。显示主要和强调色色板。”

这为整个团队提供了一个参考素材——也为客户在问“我们的十六进制代码是什么来着？”时提供了参考。

### 第 10–15 分钟：模板初始化

为客户生成 3–5 个核心模板：
- 社交媒体帖子（方形）
- Instagram 故事 / TikTok
- 电子邮件标题
- 博客特色图片
- 演示幻灯片（16:9）

这些成为基础画布。每个新素材都从一个已初始化品牌的模板开始，而不是从空白页面开始。

## 日常代理机构工作流

[图片 3 占位符 — 真实 UI 截图]

以下是典型的代理机构一天如何在 Lovart 中流转。

### 上午：通过 @commands 进行分流

Lovart 的 @commands 系统让你能够快速使用简单的英语工作。常见的代理机构命令：

- `@commands create social-post --brand "客户 A" --size 1080x1080 --template "产品发布"` — 从你的模板库生成一个品牌化的社交媒体帖子
- `@commands resize --target instagram-story` — 获取任何设计并将其适配为故事格式，智能地重新排列元素
- `@commands batch --from "内容日历.csv"` — 读取包含帖子要求的电子表格，并按顺序生成所有素材
- `@commands export --format png,jpg,pdf --quality print` — 以多种格式导出所有打开的设计

### 中午：触控编辑和审阅

Lovart 的触控编辑是人工眼力与 AI 速度的结合点。生成的设计已经完成了 90%——触控编辑为你提供了像素级的控制，以完成最后那 10% 的关键部分。调整间距、替换图像、微调字体。每次编辑都是非破坏性的，并记录在版本历史中。

对于代理机构的审阅，直接从 Lovart 分享一个设计预览链接。无需导出 PNG，无需附加到电子邮件，无需“final_v3_revised_2.png”这种文件名混乱。客户看到的是实时预览。他们评论。你迭代。

### 一天结束：客户交接

Lovart 的导出管道支持：
- 直接导出为 PNG、JPG、SVG、PDF 和 MP4（用于动画素材）
- Figma 导入（适用于使用 Figma 作为交接层的团队）
- 用于自动交付到 CMS 或 DAM 系统的 API 导出（Enterprise 计划）
- 可设置过期时间的可分享预览链接（设置 TTL：24 小时、7 天或永久）

对于使用 Enterprise 计划的代理机构，API 意味着你可以将 Lovart 直接连接到你的项目管理工具栈中——当新任务在你的 PM 工具中移动到“设计”状态时，设计会自动生成。

## 扩展到 50 多个客户

当客户超过 50 个时，你需要超越 UI 的自动化。Lovart 的 API 和 @commands 管道支持：

- **品牌工具包 API**：当你通过自己的系统引入客户时，以编程方式创建和更新品牌档案
- **模板继承**：在代理机构级别定义一个基础模板，子工作区继承它并自动应用特定于品牌的覆盖
- **使用分析**：跟踪哪些客户消耗了最多的设计资源，识别瓶颈，并合理调整你的计划
- **自动质量保证**：定义品牌合规规则（logo 必须有 24px 内边距，标题字体必须是 Inter Bold），Lovart 会在导出前标记违规行为

我们看到代理机构通过 Lovart 经历三个阶段：

**阶段 1：采用（第 1–2 个月）**
一个超级用户倡导 Lovart。他们构建了第一个品牌工具包和模板。产出增加了 2–3 倍。团队持怀疑态度但充满好奇。

**阶段 2：整合（第 3–6 个月）**
整个团队都在使用 Lovart。工作区已标准化。@commands 成为日常工作流程的一部分。设计审阅在应用内进行。客户注意到周转速度更快。代理机构开始凭借速度赢得竞标。
