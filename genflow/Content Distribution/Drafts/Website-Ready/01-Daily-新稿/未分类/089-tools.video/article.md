## 👤 测评人背景

内容分发里最常见的「小麻烦」不是剪大片，而是：客户丢来一个 2GB 的 MOV、培训录像不能上公网、封面要抽一帧、音频要单独提出来喂 ASR。CloudConvert 一类云转换又快又熟，但我不敢把未上线素材和内部培训片传上去。本机装 HandBrake 又嫌「为一次压缩开软件」。tools.video 声称 26 种工具全在浏览器本地跑、最大支持 50GB、不用注册——听起来像专治这种纠结。我按夹内笔记与公开口径拆：它能替掉哪些上传站，又绝对替不掉什么。

---

## 🎯 先说结论

tools.video 是 SubEasy.ai 做的 **纯浏览器音视频工具箱**：压缩、转换、剪辑、变速、字幕、音频提取等常用项集中在一个站点，处理走 mediabunny + ffmpeg.wasm，文件**不上传服务器**（笔记与官方叙事一致；可用断网缓存后自测验证）。免费、免登录；首次要拉约 30MB 的 wasm，之后可离线用缓存。适合隐私敏感、偶尔处理单文件的创作者与运营；要批量 API、专业调色多轨，或指望老手机飞快转 4K，它不是答案。

**我的决策句：你经常处理「不能上传」的单文件压缩/转换/抽音，优先把 https://tools.video 收进书签并固定用 Chrome/Edge；要批处理流水线或达芬奇级剪辑，不建议拿它当主力——HandBrake / 本地 ffmpeg / 专业 NLE 各司其职。**

## 📦 tools.video 是什么？

它不是又一个「上传 → 排队 → 下载」的云转码站，而是把 FFmpeg 能力搬进浏览器标签页。支持常见视频/音频容器（MP4、MOV、MKV、WebM、AVI、FLAC、WAV、AAC 等），笔记口径还提到 5.1/7.1 环绕声保留。简单了解：常和 CloudConvert、Online-Convert 并列；差异核心就一句——**文件离开不离开你的设备**。GitHub 上的 `tools.video-site` 只是官网前端，Stars 低不代表 ffmpeg.wasm 底座弱，别用站点仓 Stars 误判产品能力。

## 🧩 tools.video 有哪些功能？

总起：定位是「基础工具箱」，不是 Premiere / DaVinci 替代品。26 种工具够覆盖分发侧 80% 的「临时处置」。

### 功能特色一览

| 功能模块 | 具体表现 | 实用价值 |
|----------|----------|----------|
| 视频压缩与转换 | 质量可选、多格式互转（MP4/MOV/MKV/WebM/AVI 等） | 发平台前压体积、统一容器，且素材不上云 |
| 剪辑类快操作 | 剪辑、变速、裁剪、缩放、合并、旋转、倒放、水印、字幕等 | 小改动不必开重型工程软件 |
| 音频工作 | 提取、剪辑、转换、合并、变速 | 给 ASR/配音下一棒送干净音轨 |
| 其他 | 视频转 GIF、图片转视频、媒体信息等 | 封面动图、素材体检 |

### 视频压缩（我最常用的入口）

路径笔记写得很直白：打开 https://tools.video/video-compress → 拖文件（最大 50GB 口径）→ 选质量（可预览）→ 本机处理完下载。对我这种「周更前临时压一条」的人，价值是 **零安装 + 不上云**，不是压缩比吊打 HandBrake。

> 📷 **配图待补**：压缩页处理中状态（`images/tools-video-feature-compress.png`）

### 格式转换与音频提取

转换入口：https://tools.video/video-convert；抽音：https://tools.video/audio-extract。典型小场景：客户给 MOV，平台只要 MP4；或先抽 WAV/MP3 再丢给语音转写。记得「上传」在这里的语义是「选本地文件」，不是传到他们服务器——用词习惯要改过来，不然团队会误解隐私承诺。

> 📷 **配图待补**：音频提取结果下载（`images/tools-video-feature-audio.png`）

### 工具墙的边界

滤镜、补帧、字幕等都在列表里，但它们解决的是「快刀」，不是调色台与多轨时间线。专业成片仍回 NLE；tools.video 负责把「隐私敏感的预处理」从云站挪走。

我自己的分水岭很具体：改片头三秒、压到平台上传线、抽一轨给转写——开网页；要调色、多机位、字幕工程、版本管理——直接出门。把分水岭写进团队约定，比争论「它算不算剪辑软件」有用。

## 🧠 核心逻辑：它为什么不一样？

云转码站卖的是服务器算力；tools.video 卖的是 **算力换隐私**。

三拍：

1. **不离开设备**：处理在浏览器里完成  
2. **用成熟底座**：ffmpeg.wasm，而不是自研黑盒编解码  
3. **用完即走**：免注册，适合临时任务，不适合当媒体资产中台

**机制层怎么选**：隐私优先、单文件、现代浏览器 → 先试 tools.video；要吞吐与可脚本化 → 本地 ffmpeg/HandBrake；要云端协作与队列 → CloudConvert 一类（并接受上传风险）。

## ⚔️ tools.video 和 CloudConvert、HandBrake 有什么区别？

| 维度 | tools.video | CloudConvert 等云站 | HandBrake / 本地 ffmpeg |
|------|-------------|---------------------|-------------------------|
| 定位 | 浏览器本地工具箱 | 云端转码服务 | 本机专业/脚本转码 |
| 隐私 | 文件不上云（官方叙事） | 必须上传 | 完全本地 |
| 门槛 | 打开网页即用 | 账号/额度常见 | 要装软件或写命令 |
| 批量 | 不支持批处理/API（笔记口径） | 常有 API/套餐 | 脚本可批量 |
| 性能 | 绑本机 CPU/内存；Safari 硬件加速可能弱 | 绑云端规格 | 绑本机，通常更稳 |
| 最强场景 | 敏感单文件快处理 | 大吞吐、团队云协作 | 长期压制流水线 |

选型句：要 **隐私敏感的单文件快处理**，优先 tools.video；要 **云端批量与 API**，选 CloudConvert 并评估合规；要 **长期可脚本的压制产能**，HandBrake/ffmpeg 更合适。

## 🧪 我实际跑下来的体验

说明：工具列表、限制与 FAQ 来自夹内调研笔记与公开页面口径；站点仓 Stars 与 ffmpeg.wasm Stars 取撰写时 GitHub API。**未编造压缩比与耗时**。

### ✅ 好的方面

**1. 隐私叙事可核对**

「不上传」是这类工具唯一值得写进 SOP 的卖点。笔记建议缓存后断网自测——我认可这个验收姿势，比听广告强。

**2. 零安装，真适合「临时一刀」**

压缩、抽音、转 MP4，分发侧每周都会撞上。打开标签页比劝同事装 HandBrake 成功率高。

**3. 工具覆盖面够日常**

26 项把「发片前的脏活」收成一站，少收藏十个杂站。

**4. 免费免登录降低协作摩擦**

给外包/兼职一个链接就能干活，不用再开账号权限单。

### ❌ 不好的方面

**1. 性能完全看本机脸色**

大文件在老机器上会慢到怀疑人生。50GB 是上限口径，实际常卡在浏览器内存，不是营销数字说了算。

**2. 没有批处理 / API**

一周要压 50 条物料，它会把你点到手酸。自动化请回本地脚本。

**3. Safari 可能吃亏**

笔记写明 WebCodecs/硬件加速在 Safari 上可能不如 Chrome/Edge。团队统一浏览器能少一半扯皮。

**4. 「浏览器本地」仍有环境风险**

文件不上传 ≠ 绝对安全：浏览器扩展、恶意脚本仍可能碰页面数据。处理极敏感素材时，干净配置文件/无乱七八糟扩展，是基本礼貌。涉密项目我宁可本机 ffmpeg 命令行，也不在插了十几个购物扩展的浏览器里拖文件。

### 素材笔记里的常见问法

**Q：真的完全不上传吗？**  
官方叙事是 ffmpeg.wasm 本地执行；缓存后可断网验证。

**Q：免费吗？有大小限制吗？**  
完全免费免注册；最大 50GB 口径，实际受浏览器内存约束。

**Q：和 CloudConvert 区别？**  
对方上传云端；这边本地算——隐私换本机性能。

## ⚠️ 安装和使用需要注意什么？

### 数据会离开本机吗？

按官方与笔记口径：**处理文件不上传**。但仍要分清：你访问的是第三方网页，信任边界在站点与浏览器环境；极敏感内容可改用完全离线的本机 ffmpeg。

### 许可证允许商用吗？

站点前端仓与 ffmpeg.wasm（MIT）是两回事。自用工具箱一般无妨；若二次分发站点代码或嵌入产品，分别核对各仓 LICENSE（前端仓 SPDX 以 GitHub 当日为准，撰写时可能为空）。

### 成熟度边界

这是「快刀站」，不是媒体中台。别指望它管理版本、权限与团队审片流。
