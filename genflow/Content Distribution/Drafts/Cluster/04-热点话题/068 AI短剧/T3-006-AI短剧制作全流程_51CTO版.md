## 一、剧本与流程管理

### AIDrama Studio
**GitHub**: https://github.com/EvoLinkAI/ai-short-drama

一站式AI短剧平台，从剧本到视频输出完整管线。内置剧本模板，支持角色设定、场景描述。采用LLM驱动剧本生成，输出格式化剧本JSON。

**技术特点**：
- 基于大语言模型的剧本生成引擎
- 内置分镜模板系统
- 支持剧本导出为标准化格式

**上手难度**：★★☆☆☆
**硬件要求**：NVIDIA GPU 8GB+

**缺点**：剧本质量需人工审核，角色设定精细度不够。在实际测试中发现剧情逻辑断层问题——AI生成的剧本在长叙事下容易出现矛盾情节。

### AI-ContentCraft
**GitHub**: https://github.com/hotdancing/AI-ContentCraft

多风格短剧生成，支持古风/都市/悬疑。比AIDrama Studio更灵活，但技术门槛更高。

**技术特点**：
- 多风格渲染管线切换
- 基于Diffusion Model的角色生成
- 风格迁移后处理

**缺点**：需要一定技术配置，不同风格生成质量差异明显——古风效果最优，悬疑次之，都市效果最差。

## 二、视觉生成

### deep-printfilm
**GitHub**: https://github.com/yuanzhongqiao/deep-printfilm

剧本角色关键帧串联AI漫剧工场。角色一致性保持好，漫画风格视觉效果突出。

**技术特点**：
- 基于Stable Diffusion的漫画风格渲染
- 角色关键帧提取与一致性约束
- 跨场景角色特征映射

**部署方式**：
```bash
git clone https://github.com/yuanzhongqiao/deep-printfilm
cd deep-printfilm
pip install -r requirements.txt
python run.py
```

**缺点**：仅支持漫画风格。需GPU推理，8GB显存为最低要求。

**横向对比**：与Toonflow相比，deep-printfilm在漫画风格上更有优势，但Toonflow在风格多样性和角色一致性上更胜一筹。

### Toonflow
**GitHub**: https://github.com/HBAI-Ltd/Toonflow-app

端到端AI短剧生成工具。角色一致性在开源方案中表现最优，在角色「漂移」问题上实际验证效果领先。

**技术特点**：
- 端到端视频生成管线
- 角色嵌入向量+Cross-Attention约束实现一致性
- 支持多画风切换（二次元、写实、水墨等）

**部署方式**：
```bash
git clone https://github.com/HBAI-Ltd/Toonflow-app
cd Toonflow-app
# 推荐使用Docker
docker pull hbailtd/toonflow
docker run --gpus all -p 7860:7860 hbailtd/toonflow
```

**缺点**：GPU 8GB+，生成速度中等（3分钟短剧约需30分钟生成）。

**💡 搭档组合**：Toonflow生成 + **Jellyfish**做一致性后处理优化。

> **金句**：短剧最大的敌人不是AI不会画，而是角色会「漂移」。Toonflow+Jellyfish就是那个把角色钉在原地的技术组合。

## 三、语音合成

### 语音合成方案对比

| 工具 | 技术架构 | 特点 | 适合场景 | 部署难度 |
|------|---------|------|---------|---------|
| ChatTTS | 基于LLM的TTS | 对话自然，多角色区分 | 多角色短剧配音 | ★★☆☆☆ |
| CosyVoice | 阿里开源语音克隆 | 中文效果出色，支持克隆 | 固定角色配音 | ★★★☆☆ |
| Edge-TTS | 云端API | 100+音色，稳定可靠 | 长文本旁白 | ★☆☆☆☆ |

**部署建议**：
- 多角色对话 → ChatTTS（音色区分度最好）
- 固定主角 → CosyVoice（克隆后一致性高）
- 长篇旁白 → Edge-TTS（稳定性优先）

### Jellyfish
解决角色漂移问题，作为后处理工具使用。采用图像特征匹配+面部重建的技术路线。

**技术特点**：
- 基于特征匹配的角色检测
- 面部区域的局部重绘
- 时序一致性约束

**缺点**：单独效果有限，需配合Toonflow使用。

### 火包短剧(huobao-drama)
**GitHub**: https://github.com/chatfire-AI/huobao-drama

专注中文短剧场景，一键生成。中文语境理解优于西方工具，但功能相对单一，画风选择有限。

## 四、实操流程

### 环境准备
```bash
# 基础环境
python3 -m venv drama-env
source drama-env/bin/activate
pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu118
pip install ffmpeg-python opencv-python pillow

# 各工具单独安装（见上述部署命令）
```

### 完整生产流程

```
Step 1: 剧本生成
  AIDrama Studio → 输入故事大意 → 调整角色设定 → 导出剧本JSON
  耗时：15-30分钟

Step 2: 角色设计
  Toonflow → 定义角色外观 → 生成3-5张多角度参考图
  耗时：10-20分钟

Step 3: 分镜与关键帧
  deep-printfilm → 剧本转分镜稿 → 按幕生成关键帧
  耗时：30-60分钟（取决于剧本长度）

Step 4: 配音
  ChatTTS/CosyVoice → 多角色/单角色配音 → 导出音频
  耗时：5-10分钟

Step 5: 视频合成
  Toonflow → 串联关键帧+配音 → 生成原始视频
  耗时：30分钟（3分钟短剧）

Step 6: 后处理优化
  Jellyfish → 一致性后处理修复 → 最终视频
  耗时：10-15分钟

Step 7: 字幕与导出
  Whisper → 自动生成SRT字幕 → FFmpeg合成最终MP4
  耗时：5分钟
```

## 六、常见技术问题

**Q：角色漂移的根因是什么？**
A：Diffusion Model在不同时间步生成的潜变量不一致导致。Toonflow通过角色嵌入向量约束Cross-Attention，Jellyfish通过后处理特征匹配修复。两者结合可解决80%以上漂移问题。

**Q：最低硬件要求能否跑完整流程？**
A：8GB显存可运行AIDrama Studio和Toonflow基础功能；deep-printfilm和Jellyfish建议12GB+。推荐方案A（仅用AIDrama Studio）对硬件要求最低。

**Q：生成速度瓶颈在哪？**
A：Toonflow的视频生成是主要瓶颈（3分钟短剧约30分钟）。优化方向：(1)使用更小的模型蒸馏版本 (2)降低生成分辨率后再超分 (3)批量处理减少模型加载次数。

**Q：生成的短剧能否商用？**
A：各工具均为开源（MIT/Apache 2.0），但角色形象和剧本内容需自审版权。背景音乐建议使用CC0授权资源。
