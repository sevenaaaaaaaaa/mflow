# Lovart Blog Wave1 SERP 证据卡 2026-07-13

## 结论

Wave 1 这 4 篇的共同问题不是“没长度”，而是“还没把 SERP 意图翻译成真正的 winning angle”。

- `freepik-ai-image-generator-review`：高曝光低 CTR，本质是“Freepik 够不够做成品”的决策查询
- `complete-guide-consistent-ai-character-design`：搜索者想要的是“如何稳定锁角色”，不是泛泛角色设计
- `complete-guide-ai-animal-pet-portrait-generation`：搜索者关心 likeness、print quality、style control、是否值得付费
- `complete-guide-ai-video-model-selection-2026`：搜索者真正要的是“按 use case 选模型”，不是通用大百科

## 1. freepik-ai-image-generator-review

### GSC 信号

- clicks: `736`
- impressions: `268,718`
- CTR: `0.27%`
- avg position: `7.31`
- top query: `freepik ai`
- 次级 query：
  - `freepik ai image generator`
  - `freepik ai free`
  - `freepik image generator`

### SERP 现状

本词的前排内容主要分 3 类：

- 官方价格 / 工具页：直接承接品牌查询
- “Freepik 现在叫 Magnific” 的平台综述
- 第三方评测，强调模型数量、价格、信用点、图库捆绑价值

### 主要对手在讲什么

- `Freepik / Magnific pricing`：强调 credits、Premium / Pro / Business、图库资产与 AI 工具打包
- `AIUnpacking / Photutorial / Autoposting`：强调多模型平台、视频/音频/图库一体化，以及信用点和隐藏成本
- `Lovart 自己的 alternatives 文`：强调 Freepik 是 bundle，Lovart 是 AI-native design workflow

### 当前文章的缺口

- 已经做了 signal refresh，但仍像“品牌评测 + Lovart 导流”，不够像“真实购买决策文”
- 需要更明确回答：
  - Freepik 什么时候够用
  - 什么时候会卡在 stock-library mindset
  - 什么情况下应该直接换到 Lovart / Firefly / Recraft / Ideogram
- 需要把“credits / bundle / stock advantage / workflow ceiling”讲得更锋利

### 这篇怎么赢

- 不跟官方拼产品清单，要拼 **workflow decision**
- 用“图库 + 多模型 bundle 很强，但成品设计链条不够深”作为主判断
- 加入：
  - 真实适用场景
  - hidden cost / switching cost
  - 谁该留在 Freepik，谁该升级到 Lovart

## 2. complete-guide-consistent-ai-character-design

### GSC 信号

- clicks: `19`
- impressions: `13,872`
- CTR: `0.14%`
- avg position: `11.34`
- top query: `ai image generation face consistency techniques 2026`
- 次级 query：
  - `ai image generation character consistency techniques 2026`
  - `best ai image generator for character consistency 2026`
  - `best ai image model character consistency 2026`

### SERP 现状

前排内容明显集中在：

- reference-image / character-reference 工作流
- LoRA / custom model training
- IP-Adapter / InstantID / ComfyUI 这类更技术的稳定方案
- “角色漂移为什么发生、如何降低 drift”

### 主要对手在讲什么

- `Oakgen / Flick / Neolemon`：reference image 是最快可用路径
- `Apatero / Black Forest Labs`：LoRA 训练是长期高一致性的上限
- `Scenario / Ideogram`：单图角色一致性适合低门槛快速锁脸

### 当前文章的缺口

- 现有长文很长，但导语仍偏“角色设计总论”
- 需要更快回答搜索者真正的问题：
  - 最快的可行方法是什么
  - 什么情况下只用 reference 就够
  - 什么情况下必须 LoRA
  - 如何避免 drift、pose collapse、outfit bleed

### 这篇怎么赢

- 把整篇 guide 重心从“角色一致性很重要”改成“reference -> lock -> repair -> train”的层级决策
- 加入：
  - 单图锁定 vs 多参考 vs LoRA 的适用边界
  - 一致性不是 prompt 魔法，而是 identity system
  - 什么时候 Lovart 足够，什么时候要进 ComfyUI / LoRA

## 3. complete-guide-ai-animal-pet-portrait-generation

### GSC 信号

- clicks: `5`
- impressions: `648`
- CTR: `0.77%`
- avg position: `8.51`
- top query: `what are the best digital tools and services available for creating ai-generated pet portraits?`
- 次级 query：
  - `what features does an online photorealistic ai pet portrait generator offer?`
  - `what features does an ai pet portrait generator with photorealistic quality offer`
  - `what are the latest ai pet portrait generators available today`

### SERP 现状

当前 SERP 主要是 3 种内容：

- “best pet portrait generators” 榜单
- 针对宠物肖像的垂类产品页 / 应用页
- 强调 print-ready / likeness / style presets 的购买导向文章

### 主要对手在讲什么

- `TrexPicks / PawDressed / Neolemon`：非常强调 likeness、breed detail、print resolution、一次性 portrait vs recurring character
- `DIYAI / Adobe Firefly`：强调控制力、编辑能力、商用安全、快速测试

### 当前文章的缺口

- 文章已经很长，但前段重复较多，用户意图压缩得不够快
- 需要更明确回答：
  - 单次送礼肖像和可重复宠物角色不是一回事
  - print-ready 与 social-only 的工具选择完全不同
  - likeness、fur detail、background control、resolution transparency 才是关键购买点

### 这篇怎么赢

- 从“宠物肖像大而全”转向“按用途分流”的 complete guide
- 加入：
  - single gift / memorial / merch / mascot 四种用法
  - print quality 与 recognizability 判断标准
  - 通用工具与垂类宠物工具的 trade-off

## 4. complete-guide-ai-video-model-selection-2026

### GSC 信号

- 当前 GSC page 口径：`0`
- 但主题本身是高价值 broad-intent，且属于可做 cluster 支柱的 complete guide
- 当前应按 topic / SERP 主导，而不是按现有点击主导

### SERP 现状

当前前排内容基本在做：

- `Sora vs Runway vs Kling vs Pika` 的 use-case 选择
- “没有一个最好，按项目选”
- clip-tier vs pipeline-tier
- premium cinematic vs cheap iteration vs social-first vs editor-first

### 主要对手在讲什么

- `Yotta Labs / UlazAI / PixVerse / Pixflow / M Studio`
- 共识非常明确：
  - Runway = editor-first / control
  - Veo = premium realism
  - Kling = value / motion / iteration
  - Pika = social / fast experiments
  - Sora = benchmark / concept prestige，不一定是最实用生产路线

### 当前文章的缺口

- 当前英文 published 文前段有明显语言污染，影响可信度
- 文章方向是对的，但需要更明确地做成 **use-case-first decision guide**
- 不能停留在“模型百科”，要变成：
  - 单英雄片段选谁
  - 高迭代广告选谁
  - 长流程 storyboard / pipeline 选谁
  - 什么时候 Lovart 该作为 orchestration layer，而不是底层模型替代品

### 这篇怎么赢

- 核心打法不是列模型，而是列 **决策框架**
- 用“job-to-be-done -> winner / runner-up / why / next step”替代泛比较
- 把 `Sora` 从 idol 位置降回 benchmark 位置，把实际可买、可测、可交付的模型放前面

## Wave 1 统一判断

这 4 篇的共同升级方向是：

- 从“signal refresh 合格稿”升级为“强判断型支柱内容”
- 不再追求泛泛完整，而要更快给出：
  - 谁适合什么
  - 为什么
  - 什么时候别用
  - 下一步该怎么做
