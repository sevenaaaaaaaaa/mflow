# 设计复刻能力 · 产品化规划（v0 规划稿）

> **来源**：2026-10-06 lovart.ai composite-page-all → WordPress 复刻实战（全链路已验证：探测→CSS/tokens 提取→33 组件切分→区块映射→深浅色→截图对比基准）。
> **问题**：这套能力 MFlow 和 WebFlow 都需要——是集中做一个复刻服务（API），还是各自开发？

## 一、把这次实战拆开：复刻 = 8 环节流水线

| # | 环节 | 做什么 | 平台无关？ |
|---|---|---|---|
| 1 | **源探测** | 可达性 / SSR vs CSR 判定（决定直取 HTML 还是 headless 渲染）/ 技术栈指纹 | ✅ 完全无关 |
| 2 | **设计资产提取** | 编译 CSS 抓取合并（364KB）/ CSS 变量 tokens（381 项）/ 字体栈 / 断点清单 | ✅ 完全无关 |
| 3 | **结构切分** | 按锚点切组件（data-lp-section 等可配置策略）/ 修边（预览工具、脚本、页尾）/ div 平衡闭合 | ✅ 完全无关 |
| 4 | **中间表示 IR** | 组件包 `{type, html, css依赖, assets, manifest}`——**平台无关契约** | ✅ 完全无关 |
| 5 | **目标映射** | IR → 各家区块/组件（MFlow：Gutenberg `lovart/{type}`；WebFlow：它的组件体系） | ❌ 强耦合目标平台 |
| 6 | **资源工程** | URL 绝对化 → 媒体本地化 → 防盗链处理 | ⚠️ 半通用（本地化目标不同） |
| 7 | **主题/模式适配** | 深浅色（class-based vs prefers）、响应式断点验证、字体 fallback | ✅ 机制无关，参数品牌化 |
| 8 | **QA 回路** | 浏览器截图对比基准 + 逐项断言脚本 | ✅ 完全无关 |

**分界线**：环节 1-4 + 7-8 是纯技术机制、平台无关、**稳定性优先**；环节 5-6 是目标平台强耦合、**场景差异所在**、迭代快。

## 二、三个选项与推荐

| 选项 | 形态 | 问题 |
|---|---|---|
| A · 全集中 API | 一个复刻服务：输入 URL → 输出成品页面 | "成品页面"的定义权在各产品（MFlow 要 Gutenberg+门禁+品牌红线，WebFlow 要它的）——API 被迫做到差异最大的最后一公里，**服务会膨胀成两套** |
| B · 全分布 | 各产品自建全部 8 环节 | 环节 1-4 重复造轮子且质量发散（抓取边界/修边规则/tokens 提取都是这次踩过坑的） |
| **C · 核心 SDK + 平台适配器（推荐）** | `replication-core`（环节 1-4+7-8，产出 IR）+ 各产品适配器（环节 5-6 消费 IR） | 集中与分布各得其所 |

**推荐 C 的理由**：
- 瓶颈环节（抓取边界/切分/修边/tokens/QA）是这次实战踩坑最多的，值得集中沉淀一次
- 最后一公里（映射到各家组件）天然必须各自实现——适配器模式顺势分层
- **C 可以进化成 A**：SDK 核心包上 API 壳就是服务，不必二选一；先 SDK（无运维、离线可用），有第三方需求再 API 化

## 三、各产品消化方式

### MFlow（场景：多品牌内容工厂，复刻 = 品牌设计系统接入）
- 接入点：brand profile 增 `designSource` 字段（声明源 URL）→ 引擎产出 IR → 现有 `wp_blocks.py` 适配器（规划中）消费 IR → Gutenberg 区块 → 既有管线（门禁/排程/体验层）
- 复刻在 MFlow 的语义：**一次性接入 + 组件级增量**（新品牌接入、主站上新组件）——不是每篇内容都跑
- MFlow 特有且不进引擎的：KB/表达红线/门禁/发布 dry-run 闸（这些是 MFlow 内容治理，与复刻无关）

### WebFlow（场景待补充）
需要你补充三个信息才能定它的适配器形态：
1. 它的**目标输出**是什么形态？（React 组件库 / Webflow CMS / 静态站 / 其他）
2. 典型**源站类型**？（同为主站官网级 SSR？还是任意小站/CSR 为主？——决定 headless 渲染是否为必备）
3. 是否需要 MFlow 同款**内容治理**（KB/红线/门禁）？

## 四、已知边界（实战教训，写进引擎文档）

1. **SSR 前提**：直取 HTML 要求源页服务端渲染；CSR 站点需 headless 渲染（能力升级项，v1 不做）
2. **交互 JS 不移植**：只复刻静态形态（跑马灯滚动/tabs 切换/下拉是源站私有 JS）——动效需逐个重写
3. **私有字体不可移植**：Feature-Deck 类私有字体只能 fallback（Instrument Serif 顶位）
4. **防盗链资源**：外链图片可能不显示 → 媒体本地化是标准步骤
5. **预览工具不是页面**：源页自带的编辑器/变体面板（VARIANTS 类）要剥离
6. **深色模式机制因站而异**：class-based（Lovart）vs prefers-color-scheme，引擎需探测
