# 开工预热（warmup）

> 目的：让 **Lovart Global** 的每一块后台都带着**真实的**历史记录、曲线、findings 和缺口清单开工，
> 而不是打开每一页都是空状态 CTA。
> 原则：**不伪造数据**——所有历史都由真实动作产生；跑不通的如实记 skip/fail。

## 为什么需要它

系统能力早已就绪（批量执行器、QA 编排、剧本、GEO、内链、报告…），
但**能力就绪 ≠ 后台有内容**。很多页面的数据要等第一次真实执行才会出现：

| 页面 | 空状态的原因 | 预热跑什么 |
|---|---|---|
| QA 编排 | 从没扫过 | 真实读 Sanity 做字段扫描 → findings |
| 批量任务 | 没有历史任务 | 落地页闭环 / alt 补齐 dry-run |
| 执行画布（Run） | 没跑过剧本 | 跑一次 dry-run 剧本 |
| 自动化 | 剧本没装 | OPC 一键装启 4 个推荐剧本 + 逐个试运行预览 |
| GEO 仪表 | 没探测过 | 真实引用探测（有 Key 才跑） |
| 内容库 | 镜像为空 | `--sync-library` 全量拉取 |
| 报告中心 | 没生成过 | 月度自我迭代回顾 + 内链建议报告 |
| 自我迭代仪表 | 无 QA 历史 | 由上面的 QA 扫描回流 |
| 收件箱 / 治理面板 | 无输入 | 由前面各步真实产出 |

## 安全边界

- 全部动作**只读或 dry-run**，**不写生产库**。
- 脚本**不提供** `--real` 开关——要真写，走后台的人工授权路径（这是不可协商的铁律）。
- 幂等：重复跑只会多出几条真实历史，不会破坏状态。
- 每一步的失败/跳过都写进报告，**不补数、不美化**。

## 用法

```bash
# 在服务器上（密码自动从 run/env.sh 读）
bash "1-4 Dev/scripts/warmup.sh"

# 只跑某几个板块
bash "1-4 Dev/scripts/warmup.sh" --only A,B

# 含内容库全量同步（17.5k 篇，约 3 分钟）
bash "1-4 Dev/scripts/warmup.sh" --sync-library

# 从别的机器指向线上
python3 "1-4 Dev/scripts/warmup.py" --base https://nownexts.com/mflow --password ...
```

常用参数：`--limit`（每个 dry-run 预设的条数上限，默认 30）·
`--qa-max`（QA 扫描页数上限，默认 200）· `--wait`（单任务最长等待秒数，默认 300）。

## 板块

| 板块 | 覆盖 |
|:--:|---|
| **0** | 健康基线 · 系统自检 · 一键自愈 · RAG 检索底座 |
| **A** | 内容库状态/同步 · 多语言覆盖盘点 · 发布通道连通 · 落地页闭环 dry-run · 发布历史 |
| **B** | QA 扫描（真实读 Sanity）· findings 归类 · 修复编排 dry-run · 复检 delta · 图片物料台账 · alt 补齐 dry-run |
| **C** | OPC 一键装启推荐剧本 · 全部剧本试运行预览 · 跑一次 dry-run 剧本 · Agent 任务台真实一轮 · 执行画布历史 |
| **D** | GEO 引用探测 · 引用记录 · 效果归因 · 内链建议体检 · 月度自我迭代回顾 · 报告中心 |
| **E** | 失败→学习扫描 · 降噪治理预览 · 治理面板 · 统一收件箱 · 健康终态 |

## 输出

- 终端逐步打印 `✓ / — / ✗`
- 报告落 `run/logs/warmup-YYYYMMDD-HHMM.md`（含每步结果、需处理项、被跳过项）
- 退出码：`0` 无 fail · `1` 有 fail · `2` 登录/密码问题

## 读报告的姿势

- **✗ fail** → 真故障，按报告「需要处理」段落逐条看。
- **— skip** → 多半是**缺配置或缺数据**，不是故障。典型：GEO 未配品牌词、发布通道缺 WordPress 凭证、
  内容库为空。这些属于 `docs/capability-matrix.md` 里的「用户侧待办」。
- **0 findings / 0 引用** 会如实显示为 0，**不会被补成好看的数字**——这是设计要求。
