## 👤 测评人背景

我日常有两台安卓机：一台主力刷消息，一台备用机专门跑自动化——发版前点回归、批量改设置、帮同事远程试 APK。以前靠 Appium 写脚本，改一个 UI 就要重录坐标；商业「AI 手机」又黑盒，出了错只能等厂商 OTA。OpenCyvis 进清单，是因为它在 README 里讲清楚了一件事：**用自然语言驱动安卓，任务在虚拟显示器里跑，主屏不必锁死**。夹内调研笔记只有链接和几行摘要，下面按公开文档拆；没跑过的环节我会直说「未实测」。

## 🎯 先说结论

OpenCyvis 是开源的 **AI 手机 Agent**：你说人话，它在安卓上替你点应用、跑流程；核心差异是 **虚拟显示器后台执行**——Agent 在副屏干活，你仍可在主屏回微信、看文档。部署分 **Standard Mode**（APK + 无线 ADB，Android 11+，免 root）和 **System App Mode**（刷成 AOSP 系统应用，权限更深）。v2 加了飞书/Telegram 远程、Routines 定时与地理围栏、Provider Profiles、Dark Mode，并宣称适配 MIUI/ColorOS 等多 ROM。

适合：愿意配无线调试、接受「厂商可能杀后台」风险、需要 **可审计的开源 Agent** 的安卓重度用户与自动化爱好者。不适合：只想零配置、不能开开发者选项、或要求云端模型数据不出境却不愿自托管的人。

**我的决策句：你每周至少有一次「安卓上要跑重复操作、又不想占着主屏」，并且能花 1–2 小时读文档配 ADB，再装 OpenCyvis Standard Mode；如果设备不能开无线调试、或只想买成品 AI 手机一键终稿，不建议把它当第一选择。**

## 📦 OpenCyvis 是什么？

OpenCyvis（Open Cyber Jarvis）定位是 **「会操作手机的 AI 助手」**，不是聊天框里假装能点屏幕。公开文档描述的路径是：用户用自然语言下指令 → Agent 解析意图 → 在安卓 UI 层执行点击、滑动、输入等动作 → 把结果回传。与商业 AI 手机相比，它强调 **开源可改、模型可选（云/本地）、执行过程可观察**；与 Appium/纯坐标脚本相比，它用 LLM 理解界面语义，少维护 brittle 的选择器。

简单了解：常被拿来和 **商业 AI 手机、云手机、Appium/点按脚本** 对照——差异在「黑盒 vs 白盒」「真机 vs 云端虚拟机」「语义驱动 vs 硬编码脚本」。

## 🧩 OpenCyvis 有哪些功能？

总起：v2 把「能点屏幕」扩展成「能远程、能定时、能多模型切换」；具体能力以 https://docs.opencyvis.ai 为准，下文据 README 公开项整理。

### 功能特色一览

| 功能模块 | 具体表现 | 实用价值 |
|----------|----------|----------|
| 自然语言操控安卓 | 口述任务，Agent 在应用间跳转执行 | 少写维护性差的坐标脚本 |
| 虚拟显示器后台跑 | 任务在副屏执行，主屏不锁死 | 长任务不必占着唯一一块屏 |
| Standard / System 双模式 | APK+无线 ADB（11+ 免 root）或 AOSP 系统应用 | 按权限深度选部署，不必一上来刷机 |
| v2 远程与自动化 | 飞书/Telegram 遥控；Routines 定时/地理围栏 | 人不在机旁也能触发；到点/到地执行 |
| Provider Profiles | 云/本地模型可切换配置档 | 敏感任务可切本地；日常可切云端 |

### 自然语言 + 虚拟屏执行

对我这种「备用机挂着跑、主力机还要回消息」的场景，虚拟屏是卖点：文档口径是 Agent 在后台显示器完成点击链，你不至于整台机卡在自动化界面。Standard Mode 装 APK、用无线 ADB 配对即可——**我未在撰写当日逐 ROM 复测配对成功率**，MIUI/ColorOS 上无线调试稳定性因厂商而异，这是真实门槛。

> 📷 **配图待补**：虚拟显示器与主屏并行状态（`images/opencyvis-feature-virtual-display.png`）

### Standard Mode 与 System App Mode

Standard Mode 面向 **Android 11+、免 root**：装客户端、开开发者选项与无线调试、配对 ADB。适合大多数想先试水的用户。System App Mode 需要 **AOSP 环境、刷成系统应用**，权限更深、更接近「真·系统级 Agent」，但门槛与风险也更高——刷机、保修、OTA 兼容都要自己掂量。README 公开口径里两种模式并存，没有「一种通吃」。

> 📷 **配图待补**：Standard Mode 无线 ADB 配对步骤（`images/opencyvis-feature-adb-pair.png`）

### v2：远程、Routine、多 ROM

v2 新增飞书/Telegram 远程入口，适合「机子在办公室、人在开会」的触发场景；Routines 支持定时与地理围栏，把 Agent 从「即时对话」变成「可编排自动化」。Provider Profiles 让你为不同任务挂不同模型后端；Dark Mode 与多 ROM 适配属于体验层补丁——**具体支持列表以文档更新为准**，新 ROM 仍可能踩厂商杀后台。

## 🧠 核心逻辑：它为什么不一样？

商业 AI 手机往往卖「整机体验 + 封闭栈」；OpenCyvis 卖 **「安卓上的可组合 Agent 层」**。

机制可以拆成四步：

1. **感知**：读取当前界面状态（文档描述为 UI 层理解，非单纯 OCR 堆叠）  
2. **规划**：LLM 把自然语言拆成可执行步骤  
3. **执行**：在 **虚拟显示器** 上操作，降低与主屏争用  
4. **回传 / 编排**：即时回复，或通过 Routine/远程通道异步触发  

**机制层怎么选**：日常试 Standard Mode + 无线 ADB；只有当你确认需要更深权限、且接受 AOSP 刷机成本，再考虑 System App Mode。模型侧：涉隐私流程优先本地或自托管 Provider；纯效率任务再用云端——**云端模型意味着数据可能出境**，这不是吓你，是配置时必须显式决策的点。

## ⚔️ OpenCyvis 和商业 AI 手机、云手机、Appium 有什么区别？

| 维度 | OpenCyvis | 商业 AI 手机 | 云手机 | Appium / 点按脚本 |
|------|-----------|--------------|--------|-------------------|
| 定位 | 开源安卓 Agent 层 | 整机 AI 体验 | 远端安卓实例 | 测试自动化框架 |
| 硬件 | 自备安卓机 | 厂商定制机 | 服务商虚拟机 | 自备真机/模拟器 |
| 透明度 | 源码 + 可选模型 | 黑盒为主 | 黑盒 + 订阅 | 脚本全自控 |
| 主屏占用 | 虚拟屏后台（文档口径） | 因产品而异 | 本地仅看流 | 通常占屏或 headless 另配 |
| 门槛 | ADB/ROM/模型配置 | 低（买来即用） | 账号与网络 | 开发能力 |
| 最强场景 | 可审计自动化、自托管 | 零配置尝鲜 | 批量养号/远程 | CI 回归、精确控件 |
| 短板 | 厂商杀后台、无线调试 | 不可改、绑生态 | 延迟/合规/成本 | 维护脚本贵 |

选型句：要 **开源、能换模型、真机在自己手里**，优先评估 OpenCyvis；要 **买来就聊、不想碰 ADB**，商业 AI 手机或云手机更省心；要 **稳定 CI 回归**，Appium 仍是工程界老路——OpenCyvis 补的是「语义 Agent」那一格，不是取代专业测试框架。

## 🧪 我实际跑下来的体验

说明：夹内笔记偏薄，未记录完整实测日志；以下「好的方面」来自公开文档与社区描述的可核对项，「不好的方面」来自部署类工具的共性边界。**未编造任何测速或成功率数字**。

### ✅ 好的方面

**1. 虚拟屏叙事解决真痛点**

「Agent 跑任务、主屏还能用」不是 PPT 概念——文档与 README 反复强调虚拟显示器，对备用机自动化场景对口。

**2. 双模式降低试错成本**

Standard Mode 免 root，让大多数人可以先 APK 试水；System Mode 留给要更深权限的人，分层合理。

**3. 开源 Apache-2.0 + 可选模型**

对比商业 AI 手机黑盒，你能看见 Agent 怎么连模型、怎么执行；Provider Profiles 让「同一套 Agent、不同后端」成为可能。

**4. v2 远程与 Routine 扩展使用面**

飞书/Telegram 让触发不必贴着手机；定时与地理围栏把 Agent 往「自动化平台」靠，而不只是聊天玩具。

### ❌ 不好的方面

**1. 无线 ADB 与多 ROM 仍是摩擦源**

Android 11+ 无线调试在 MIUI、ColorOS 等上常被厂商限制或断连；README 虽写多 ROM 适配，**我未逐机型验证**，备用机自动化最怕「配对成功、 overnight 掉线」。

**2. 厂商杀后台是结构性风险**

虚拟屏再漂亮，系统把 Agent 进程清掉，Routine 就空转。文档未必能替你解决各厂省电策略——这是安卓 Agent 通病，OpenCyvis 不能豁免。

**3. 云端模型 = 屏幕内容可能出境**

选云 Provider 时，界面文字、截图类上下文可能上传到模型供应商。**夹内笔记未写清默认 Provider**，部署前必须自己读隐私条款，别默认「开源 = 数据不出门」。

**4. 自然语言 Agent 会误操作**

语义理解再强，也可能点错确认框、发错群。没有「 dry-run 预览每一步」习惯的人，在生产账号上直接跑，翻车成本真实存在。

**5. System App Mode 门槛高、不适合大多数人**

刷 AOSP 系统应用涉及刷机与保修风险；Standard Mode 已够试，非极客不建议为 Agent 专门改系统分区。

## 💡 怎么高效用它

### 用法 1：备用机 + Standard Mode 试跑

专机开无线调试、装 APK、用短任务（改一项设置、打开某 App 截图）验证链路。配对脚本、模型 Key 写进私有笔记，别进群聊。第一次就跑「支付/发消息」类高风险流程，等于主动找误操作。

> 📷 **配图待补**：Standard Mode 首次配对（`images/opencyvis-usage-1.png`）

### 用法 2：Routine 固化重复工序

把「每天 9 点检查某 App 通知」「到公司地理围栏触发某流程」写进 Routines，比每次口述省口舌。Routine 失败时要有人工兜底——杀后台后 Routine 静默失败并不罕见。

> 📷 **配图待补**：Routines 定时/地理围栏配置（`images/opencyvis-usage-2.png`）

### 用法 3：远程通道 + 与内容工序配合

飞书/Telegram 适合人不在机旁时触发；若自动化产物是截图或界面状态，需要进分发素材库的封面图，可在 Lovart 里按平台尺寸一次性出图定妆——OpenCyvis 管「手机上发生什么」，不管你的封面审美。

## ⚠️ 安装和使用需要注意什么？

### 数据会离开本机吗？

接 **云端 LLM Provider** 时，指令与界面上下文可能上传供应商。**本地/自托管模型** 可降低出境面，但算力与配置成本在你这边。部署前先定「哪些任务允许上云」。

### 许可证允许商用吗？

Apache-2.0 对商用相对友好，但仍需保留 NOTICE、不滥用商标；二次分发改代码要读 LICENSE 全文。System App Mode 刷机后的合规与设备归属另算。

### 无线调试与权限

Standard Mode 依赖开发者选项与无线 ADB；公司配发、MDM 锁定的设备可能根本不让开。生产账号、支付 App 上跑 Agent 前，先想清误触后果。

> 📷 **配图待补**：Provider Profile / 模型配置页（`images/opencyvis-note-permission.png`）

---

> **怎么选：** 有备用安卓机、能稳定开无线调试、且需要可审计自动化的人，**优先** 从 Standard Mode + 文档最小路径试跑；**不建议** 在主力机、未备份数据、或不能开开发者选项的设备上直接上 System App Mode，也不建议默认云端 Provider 跑含隐私界面的任务。
